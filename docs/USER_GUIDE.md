# FeelMyRythm 사용자 지침서

> 대상: FeelMyRythm으로 개인 연습, 앙상블 동기 재생, 악보와 연습 기록을 관리하려는 사용자

개발 구조가 궁금하다면 [아키텍처와 코드 읽기 가이드](./ARCHITECTURE_AND_CODE_GUIDE.md), 현재 구현 범위를 확인하려면 [기능 카탈로그](./FEATURES.md)를 함께 보세요.

## 1. 무엇을 할 수 있나요?

FeelMyRythm은 다음 작업을 한 앱에서 처리합니다.

- 로그인 없이 개인 메트로놈, 로컬 템포맵, 로컬 악보와 개인 연습 기록 사용
- 그룹·프로젝트·레퍼토리 안에서 템포맵, 악보, 필기, 연습일지와 할일 공유
- 여러 기기가 같은 템포맵과 시작 시각으로 연주하는 앙상블 동기 세션
- PDF·이미지·MusicXML 악보 보기, 마디 매핑, 파트 전환과 재생 위치 추적
- 크로매틱 튜너와 출력 장치 지연 보정
- 브라우저 설치형 PWA 및 Capacitor iOS·Android 앱

공개 웹 주소는 `https://bonifacio.work/feelmyrythm/`입니다. 모바일 앱은 같은 화면을 사용하지만 Google 로그인, 서명 설치, Universal Link/App Link 등 일부 항목은 배포 설정이나 실제 기기 검증이 필요합니다.

현재 공개 웹은 중앙 계정과 서버 전용 external local volume을 사용하는 단일 서버 운영 구성입니다. 데스크톱 상단 정보 아이콘이나 모바일 `더보기`에서 `현재 운영 구성`을 필요할 때 열어 볼 수 있으며 첫 진입을 팝업이 가로막지 않습니다. 중앙 SSO와 local volume은 이미 적용됐습니다. S3는 다중 서버·off-host object storage가 필요할 때만 선택하고, 앱 SMTP는 중앙 SSO가 가입·복구를 맡는 동안 사용하지 않습니다. 서버 악보 volume backup은 데이터 보존 수준에 따른 권장 사항이며, mobile association과 Audiveris는 각각 서명된 모바일 출시·OMR 기능 활성화 시에만 필요합니다.

## 2. 화면과 메뉴

### 데스크톱

왼쪽 메뉴에서 다음 화면으로 이동합니다. 오른쪽 위에는 설정과 로그인 또는 현재 계정이 표시됩니다.
데스크톱 웹 상단이나 모바일 `더보기`의 `← Bonifacio`를 누르면 같은 탭에서 Bonifacio 포트폴리오 홈으로 돌아갑니다.

| 메뉴 | 하는 일 | 로그인 필요 |
| --- | --- | --- |
| 메트로놈 | BPM·박자·강세·예비박을 조절하고 템포맵 재생 | 아니요 |
| 템포맵 | 곡 구간, 템포 변화, 반복·볼타·D.C./D.S./Coda 편집 | 로컬은 아니요, 공유 저장은 필요 |
| 앙상블 | 방 생성·참가, 준비 상태, 동기 시작·정지 | 예 |
| 악보 | PDF·이미지·MusicXML 보기, 마디 매핑과 필기 | 로컬은 아니요, 공유는 필요 |
| 연습 | Markdown 연습일지와 담당자·기한이 있는 할일 | 로컬은 아니요, 공유는 필요 |
| 튜너 | 마이크로 음높이와 센트 편차 확인 | 아니요, 마이크 권한 필요 |
| 프로젝트 | 그룹·프로젝트·레퍼토리와 멤버 관리 | 예 |
| 출력 보정 | 기기·출력 장치의 클릭 지연 측정 | 저장·동기 범위에 따라 선택 |
| 설정 | 테마, 예비박, 볼륨, 시각 오프셋, 저장 공간과 계정 | 일부 계정 기능만 필요 |

### 모바일

폭 839px 이하에서는 상단바 없이 하단의 `메트로놈`, `악보`, `앙상블`, `연습`, `더보기`로 이동합니다. `더보기`에서 Bonifacio 복귀, 테마 전환, 설정, 계정·로그인, 운영 안내와 템포맵, 튜너, 프로젝트, 출력 보정, 개인정보·계정 삭제 화면을 엽니다. 840px 이상에서는 상단바를 유지합니다.
브라우저에서는 모바일 `더보기` 또는 데스크톱 상단의 `← Bonifacio`로 포트폴리오 홈에 돌아갈 수 있습니다. Capacitor 네이티브 앱에는 이 웹 전용 링크를 표시하지 않습니다.

로그인한 상태에서 레퍼토리를 정하지 않고 `연습`을 누르면 `프로젝트` 화면으로 이동합니다. 연습할 곡의 레퍼토리 행을 누르면 그 곡의 연습일지가 열립니다. 비로그인 상태의 `연습`은 이 기기의 로컬 일지를 바로 엽니다.

## 3. 빠른 시작

### 혼자 연습하기

1. 앱을 열면 `메트로놈` 화면이 표시됩니다.
2. 모바일에서는 원형 박 아래 현재 속도 숫자를 눌러 직접 입력합니다. 데스크톱에서는 큰 BPM 숫자를 누릅니다. 단계 버튼과 `탭 템포`로도 속도를 맞출 수 있습니다. 모바일 단계 버튼은 `-5`, `+5`이며 오른쪽 `탭`을 누르면 큰 탭 입력판이 열립니다.
3. 필요하면 `세부 설정` 또는 화면의 설정 영역에서 예비박 켬/끔, 강세 패턴, 볼륨과 박자를 바꿉니다.
4. 가운데 재생 버튼을 누릅니다.
5. 곡 구조가 필요하면 `템포맵`에서 구간별 BPM과 박자를 저장하고 `메트로놈에서 열기`를 누릅니다.
6. 악보를 보려면 `악보`에서 파일을 추가하고, 연습 메모는 `연습`에 기록합니다.

로그인하지 않은 데이터는 이 기기에 저장됩니다. 브라우저 사이트 데이터나 앱 데이터를 지우면 복구할 서버 사본이 없으므로 중요한 템포맵은 JSON으로 내보내 두는 것이 좋습니다.

### 앙상블과 함께 시작하기

1. 모든 참가자가 계정을 만들고 이메일 확인을 완료합니다.
2. owner가 `프로젝트`에서 그룹을 만들고, 가입이 끝난 이메일로 멤버를 초대합니다.
3. 그룹에 프로젝트와 레퍼토리를 만들고 레퍼토리에 템포맵을 저장합니다.
4. 각 기기에서 `출력 보정`을 실행합니다. Bluetooth는 지연이 크므로 가능하면 내장 스피커나 유선을 사용합니다.
5. leader가 `앙상블`에서 레퍼토리를 고르고 방을 만듭니다.
6. 초대 링크나 방 ID를 참가자에게 전달합니다.
7. 참가자는 방에 들어와 `준비` 상태를 켭니다.
8. leader가 시작 마디·반복 pass·예비박을 확인하고 시작합니다.

서버는 각 클릭을 전송하지 않습니다. 모든 기기는 고정된 템포맵 revision과 서버 시작 시각을 받아 자기 오디오 시계로 재생합니다.

## 4. 계정 만들기와 로그인

### 이메일 계정 만들기

1. `로그인` 화면에서 `처음인가요? 계정 만들기`를 선택합니다.
2. 이름과 이메일을 입력합니다. 이 단계에서는 비밀번호를 입력하지 않습니다.
3. `계정 만들기`를 누른 뒤 받은편지함과 스팸함을 확인합니다.
4. 인증 메일의 링크를 엽니다.
5. 링크 화면에서 8–128자의 새 비밀번호를 두 번 입력합니다.
6. `비밀번호 설정하고 계정 만들기`를 누르면 이메일 확인과 계정 생성이 완료됩니다.

메일이 오지 않으면 `인증 메일 다시 보내기`를 사용합니다. 재전송에는 짧은 대기 시간이 있을 수 있습니다. 링크의 인증 정보는 보안을 위해 새로고침 뒤 복원되지 않으므로 만료되거나 화면을 새로고침했다면 메일 링크를 다시 여세요.

### 이메일 로그인

1. 이메일과 비밀번호를 입력합니다.
2. `로그인`을 누릅니다.
3. 이메일 확인 전이라면 먼저 인증 메일 절차를 마쳐야 합니다.

`bonifacio.work`의 SSO 운영에서는 중앙 관리자가 만든 통합 로그인 계정을 사용합니다. 첫 접속에서 중앙 세션을 확인한 뒤 FeelMyRythm 계정이 자동 연결·생성되며 앱의 별도 회원가입·로컬 비밀번호·인증 재전송·비밀번호 reset 폼은 표시되지 않습니다. 이후 접속은 저장된 app session을 현재 중앙 계정 아래 먼저 검증해 재사용하므로 새로고침마다 새 session을 만들지 않습니다. 중앙 계정이 바뀌거나 기존 app token이 거부되면 현재 중앙 identity로 다시 연결하며, network·server 오류나 subject/email 충돌 때는 익명 앱으로 넘어가지 않고 `중앙 세션 다시 확인` 화면을 표시합니다. 중앙 계정의 아이디나 이메일이 서로 다른 기존 앱 계정과 충돌하면 자동으로 합치지 않고 관리자 확인이 필요합니다.

현재 이 SSO 흐름은 공개 브라우저 웹의 운영 계약입니다. production 모바일 앱은 system browser의 중앙 로그인을 WebView 앱 세션으로 안전하게 교환하는 native 인증 bridge가 아직 없어 출시 승인 대상이 아닙니다. 개발용 local-auth 모바일 build의 이메일 로그인과 production SSO 모바일 로그인을 같은 기능으로 보지 마세요.

### Google 로그인

- 웹 배포에 Google OAuth가 설정된 경우 Google 버튼으로 로그인할 수 있습니다.
- Google 이메일은 확인된 Google 신원과 연결됩니다.
- local-auth 개발용 모바일 build는 이메일 가입·로그인만 지원합니다.
- production SSO 모바일 출시는 중앙 native 인증 bridge 구현 뒤에 승인합니다. Google 버튼이 없다는 이유로 production server의 local login을 열지 않습니다.

### 비밀번호를 잊었을 때

1. 로그인 화면에서 `비밀번호를 잊으셨나요?`를 선택합니다.
2. 이메일을 입력하고 재설정 메일을 요청합니다.
3. 계정 존재 여부와 관계없이 같은 접수 안내가 표시됩니다.
4. 메일 링크에서 새 비밀번호를 두 번 입력합니다.
5. 변경이 끝나면 새 비밀번호로 다시 로그인합니다. 기존 로그인 세션은 만료됩니다.

## 5. 프로젝트와 권한

공유 데이터는 다음 구조입니다.

```text
그룹
└── 프로젝트
    └── 레퍼토리(곡)
        ├── 템포맵 revision
        ├── 총보·파트보와 필기
        ├── 연습일지·할일
        └── 앙상블 세션 기록
```

### 역할

| 역할 | 주요 권한 |
| --- | --- |
| owner | 그룹 설정·삭제, 멤버 초대·역할 변경·제거, leader 권한 전체 |
| leader | 프로젝트·레퍼토리·템포맵·악보 관리, 앙상블 transport 제어 |
| member | 공유 내용 열람, 허용된 개인/공유 필기와 연습 참여, 앙상블 참가 |

### 그룹과 곡 준비

1. `프로젝트`에서 `새 그룹`을 누르고 그룹 이름을 입력합니다.
2. owner는 `멤버 초대`에서 이미 가입과 이메일 확인을 끝낸 사용자의 이메일을 입력합니다.
3. 필요하면 `멤버 관리`에서 `leader` 또는 `member` 역할을 지정합니다.
4. 그룹 안에서 `프로젝트`를 만들고 이름과 설명을 저장합니다.
5. 프로젝트에 `레퍼토리`를 추가하고 곡명과 작곡가를 입력합니다.
6. 레퍼토리 카드에서 템포맵, 악보 또는 설정으로 이동합니다.

일부 하위 정보를 불러오지 못해도 성공한 그룹과 프로젝트는 계속 표시됩니다. 화면 위의 `누락된 정보 다시 시도`를 사용하세요. 누락 상태에서는 불완전한 대상의 관리 조작이 잠길 수 있습니다.

## 6. 메트로놈 사용법

### 속도와 박자

- BPM 직접 입력: 모바일 일반 화면에서는 원형 박 아래 현재 속도 숫자를 누릅니다. 데스크톱에서는 기존 큰 BPM 숫자를 누릅니다. 입력 dialog는 휴대폰 숫자 키패드를 요청하며 20–400 범위의 정수가 아니면 입력 바로 아래에 이유를 표시합니다. 적용·취소·닫기 뒤에는 입력을 열었던 템포 조작으로 초점이 돌아갑니다. 모바일 현재 속도와 박자표는 원형 박 아래에서 확인합니다.
- `-5/+5`: 현재 구간 속도를 5 BPM씩 낮추거나 높입니다. 데스크톱의 `-1/+1`은 1 BPM씩 바꿉니다. 경계를 넘는 조작은 20 또는 400에 정확히 멈추고, 끝값에서는 더 진행할 수 없는 방향이 비활성화됩니다.
- 모바일 `탭`: 오른쪽 끝의 버튼을 누르면 조작 영역이 큰 탭 입력판으로 바뀝니다. 여는 것만으로는 BPM이 바뀌지 않습니다. 입력판을 원하는 박자에 맞춰 두드리면 첫 탭은 기준 시각이 되고 이후 탭 간격으로 BPM을 계산합니다. 우상단 ×나 Escape로 닫으면 원래 조작으로 돌아가고 탭 버튼에 초점이 복원됩니다. 열기·닫기는 측정 횟수에 포함하지 않으며 다시 열 때는 새 측정을 시작합니다.
- 데스크톱 `탭 템포`: 버튼을 직접 일정하게 두드려 BPM을 계산합니다. 모바일 입력판과 데스크톱 모두 실제 첫 입력 뒤 `다시 탭`, 이후에는 누적 횟수가 2초 동안 보여 입력 인식을 확인할 수 있고 같은 내용이 화면 읽기 도구에도 전달됩니다. 2초 넘게 쉬면 새 측정을 시작합니다.
- `박자`: 모바일에서는 현재 속도 오른쪽의 박자표를 눌러 선택 창을 엽니다. 기존 `2/4`, `3/4`, `4/4`, `5/4`, `6/8`, `9/8`, `12/8` 중 현재 구간의 박자표를 선택합니다. 기존 강세는 앞 박부터 유지하며 박수가 줄면 남는 강세를 지우고, 늘면 새 박을 보통 강세로 채웁니다. 예를 들어 4/4에서 3/4로 바꾸면 앞의 세 박 강세가 남습니다.
- `강세 패턴`: 각 박을 누를 때 `무음 → 보통 → 강박` 순서로 바뀝니다. 버튼 이름은 현재 상태와 다음 상태를 함께 알려 줍니다.
- `볼륨`: 클릭 음량을 조절합니다.
- `시작 마디`: 재생을 시작할 마디를 고릅니다. 좁거나 짧은 화면에서 빠른 입력이 보이지 않으면 `세부 설정`을 열어 같은 값을 바꿉니다.

### 재생

1. `시작 마디`를 확인합니다.
2. `세부 설정` 또는 인라인 설정에서 `예비박 켬/끔`을 선택합니다. 선택은 이 기기에 저장되며 색과 상태 글자가 함께 바뀝니다.
3. 가운데 재생 버튼을 누릅니다.
4. 모바일 화면에는 중앙의 큰 박 번호와 상단의 마디·대기·예비박 상태가 표시됩니다. 원형 박 아래에는 현재 속도 숫자와 그 옆의 박자표가 표시되며 `BPM` 글자는 숨깁니다. 데스크톱·보면대 모드는 기존 BPM과 마디 표시를 유지합니다.
5. 다시 누르면 정지합니다.

재생 중에는 가능한 환경에서 화면 꺼짐을 억제합니다. 정지, 자연 종료 또는 화면 이탈 시 절전 방지 상태가 해제됩니다.

일반 모바일 화면은 상단 왼쪽에 현재 마디와 시작 대기·예비박 상태를 보여 주고, 기존 박 원 위의 넓은 숫자 패널로 현재 본박을 크게 표시합니다. 큰 박 번호는 테두리와 둥근 모서리 없이 중앙에 표시하며 기존 fit 글자 크기의 80%를 사용합니다. panel 크기와 배치는 유지합니다. 같은 박자 안에서는 본박 숫자가 바뀌어도 글꼴 크기와 중앙 위치가 흔들리지 않습니다. 원형 박 아래에는 중심을 고정한 `103` 같은 현재 속도 숫자와 그 옆의 `4/4` 같은 박자표를 같은 baseline에 표시하며 `BPM` 글자는 숨깁니다. 박자표는 큰 박 번호 영역에 표시하지 않습니다. 진행막대가 없는 원형 박 묶음은 가로·세로 중앙에 정렬합니다. 폭 599px 이하는 header·원형 박·속도·박자표·조작·상태 영역을 제외한 남는 높이에 큰 숫자가 확장됩니다. 짧은 화면이나 200% 글자 확대에서는 최소 크기를 남기고 스크롤해 조작에 도달할 수 있습니다. 예비박 중에도 `마디 1 · 예비박 4`처럼 마디 번호가 남습니다. 개인 연습·Section 문구와 다음 구간이 없을 때의 `다음: 마지막 구간`은 모바일에서 숨깁니다. 실제 박의 진행에 맞춰 하단 메뉴 위까지의 모바일 앱 영역이 모든 콘텐츠 아래에서 주황색 `#f47a24`와 30% 불투명도로 왼쪽에서 오른쪽으로 차오릅니다. 가로 화면의 왼쪽 메뉴도 채움에서 제외하며 메뉴는 원래 배경을 유지합니다. 숫자 영역의 별도 배경 채움은 없으며 panel 크기와 숫자의 밝기 반응은 유지합니다. 정지·시작 대기·모션 감소 설정에서는 채움을 비우고 다른 화면이나 데스크톱 폭·보면대 모드로 전환하면 이 장식 배경을 제거합니다. 배경은 버튼 조작과 화면 읽기를 방해하지 않습니다. 예비박은 카운트다운, 예약 대기는 `—`로 표시합니다. 숫자는 같은 색을 유지한 채 실제 본박과 예비박에 맞춰 밝기가 부드럽게 바뀌고 세분박마다 반응하지 않습니다. 정지 중에는 고정되며 모션 감소 설정에서는 밝기 변화 없이 현재 박 번호만 바뀝니다. 데스크톱과 보면대 모드는 기존 박 시각화·진행 바와 stage의 마디 정보를 사용합니다. 모바일 일반 화면은 한 줄 중앙의 `−5 → 재생/정지 → +5`와 오른쪽 끝의 작은 `탭`으로 조작합니다. ±5와 탭의 네모 테두리·배경은 없애고 누를 수 있는 영역은 48px 이상 유지합니다. 키보드 순서도 같습니다. 탭 입력판은 화면 전체를 덮지 않고 이 조작 영역을 바꿉니다. 예비박은 세부 설정이나 인라인 설정에서 바꿉니다. 600–839px의 2열 무대와 세로 여유가 있는 화면의 빠른 시작 마디는 유지됩니다.

예약한 첫 소리가 나기 전에는 `시작 대기`와 실제로 시작할 마디의 박자표를 표시하며 박 강조나 반응 배경은 켜지지 않습니다. 예비박이 시작되면 같은 시작 마디 정보를 유지한 채 큰 카운트다운 숫자를 표시하고 일반 박 원은 겹쳐 그리지 않습니다. 박 원 안의 `1·2·3·4` 번호는 현재 마디 안의 위치입니다. 현재 박은 색뿐 아니라 더 큰 원과 강한 윤곽으로도 바뀌므로 색을 정확히 구분하지 못해도 판독할 수 있습니다. 12·16·32박처럼 한 화면에 모든 원을 읽을 수 있는 크기로 넣기 어려운 박자에서는 현재 박 번호가 든 묶음만 보이고, 양옆 말줄임표가 앞뒤에 남은 박이 있음을 뜻합니다. 박 원과 진행 바는 화면 폭뿐 아니라 높이에도 맞춰 커집니다. 모바일 일반 화면은 메뉴를 제외한 앱 영역의 가장 낮은 배경 채움으로 박의 진행을 표시하고 데스크톱·보면대 모드는 기존 박 표시 아래 진행 바를 유지합니다. 창 폭을 줄이거나 기기 방향을 바꿔도 재생을 먼저 누를 필요 없이 중앙 정렬과 선명도가 즉시 갱신됩니다. 600–839px 폭에서는 높이가 늘어나도 박 표시와 조작을 2열에 유지하고, 821px부터 남는 높이에 인라인 설정과 `시작 마디`를 다시 보여 화면 가운데를 비워 두지 않습니다. 작은 화면에서는 상태 문구를 별도 줄에 두고 숫자 영역의 높이를 조정해 재생 조작과 겹치지 않게 합니다. 매우 낮은 가로 화면에 연결 복구 안내가 함께 나오면 다음 구간 같은 보조 문구를 줄이고 최소 높이와 스크롤로 박 표시·재생·재시도 조작이 겹치지 않게 합니다. 데스크톱·보면대 모드 재생 중의 은은한 배경 광원은 마디 첫 박과 예비박 상태에서만 박 원·진행 바를 보조하고 일반박마다 깜빡이지 않습니다. 정지 중에는 보면대 모드에서도 배경 tone이 켜지지 않습니다. 모션 감소 설정에서는 배경 반응과 연속 진행 채움이 멈추고 기본 bar의 고정 track·번호·박 원은 유지됩니다.

### 모바일 집중 화면과 데스크톱 보면대 모드

모바일에서는 큰 박 번호를 누르면 앱 안에서 집중 화면으로 전환합니다. 상단의 별도 보면대 버튼은 없습니다. 큰 박 번호·원형 박·속도/박자표·재생/정지만 남고 상단·하단 메뉴와 ±5·탭·설정은 숨깁니다. 큰 번호를 다시 누르거나 입력 창이 닫힌 상태에서 `Escape`를 누르면 원래 화면으로 돌아오며 전환 중에도 오디오는 계속 재생됩니다. 일반 모바일 화면의 `세부 설정`은 테두리 없는 아이콘이며 화면 읽기 이름과 44px/터치 기기 48px의 누르는 영역은 유지합니다.

데스크톱의 `보면대 모드`는 카드 모서리 없이 화면 가장자리까지 박, BPM과 마디를 크게 보여 줍니다. BPM 입력, 템포맵 편집, 설정과 개인 연습 문맥은 숨겨져 키보드 초점도 들어가지 않으며 나가기와 재생 같은 안전 조작만 남습니다. 화면 뒤의 상단·측면·하단 내비게이션도 Tab 순서에서 잠기므로 보이지 않는 링크로 초점이 빠지지 않습니다. 템포맵을 불러오는 상태나 복구 안내가 있으면 별도 줄에 유지되지만 박·마디와 재생 버튼을 밀거나 겹치지 않습니다. 높이가 극단적으로 낮은 가로 화면에서는 요소를 겹치는 대신 세로로 스크롤할 수 있으므로 재생 조작까지 내려가 사용할 수 있습니다. 화면의 나가기 조작, `Escape`, 또는 빈 영역 더블 탭으로 종료합니다. 입력 버튼 위의 두 번 탭은 종료 제스처로 처리하지 않습니다.

### 서버 템포맵과 오프라인 상태

레퍼토리 문맥에서 열면 서버 템포맵을 먼저 확인합니다. 실제 네트워크 단절이고 검증된 사용자별 사본이 있을 때만 오프라인 사본으로 연습할 수 있습니다. 이때 서버 데이터를 바꾸는 기능은 잠깁니다. 권한 오류, 삭제된 데이터 또는 서버 오류를 오래된 캐시로 대신 보여 주지는 않습니다.

## 7. 템포맵 편집기

### 기본 편집 순서

1. `템포맵`을 열고 전체 마디 수, 예비박과 못갖춘마디를 확인합니다.
2. 구간을 선택해 이름, 시작·끝 마디, BPM, 박자, 박 단위, 분할 클릭과 강세를 입력합니다.
3. 템포가 점진적으로 변하면 rit./accel. 목표 BPM을 입력합니다.
4. 필요한 만큼 구간을 나누거나 합치고 순서를 조정합니다.
5. 반복·볼타, D.C., D.S., Fine, To Coda/Coda 지시를 추가합니다.
6. 전개된 총 마디와 예상 시간을 확인합니다.
7. 필드 아래 오류를 모두 해결한 뒤 저장합니다.
8. `메트로놈에서 열기`로 방금 저장한 맵을 재생합니다. 악보에서 편집기를 열었다면 `악보로 돌아가기`도 사용할 수 있습니다.

새 프로젝트 곡에 아직 템포맵이 없으면 owner/leader는 첫 초안에서 시작합니다. member는 이미 저장된 맵을 읽고 재생할 수 있으며, 첫 맵 저장이나 수정은 리더에게 요청합니다. 메트로놈이나 로컬 악보에서 열었던 로컬 맵은 로그인 중에도 같은 기기 데이터로 편집합니다.

### 파일로 옮기기

- `내보내기`: 현재 템포맵을 JSON 파일로 저장합니다.
- `가져오기`: JSON을 읽고 구조와 실제 재생 타임라인을 검증한 뒤 현재 맵에 적용합니다. 저장 대상 곡은 바뀌지 않습니다.

### 충돌과 이탈 보호

- 다른 사용자가 먼저 같은 레퍼토리 템포맵을 저장하면 자동 덮어쓰지 않고 서버 최신본 또는 내 초안 재기준을 선택하게 합니다.
- 변경 중 다른 메뉴로 이동하면 `계속 편집`, `버리고 이동`, `저장 후 이동` 중 하나를 선택합니다.
- 원격 오프라인 사본은 읽기 전용이라 저장과 가져오기를 할 수 없습니다. 연결을 복구한 뒤 다시 시도하세요.

## 8. 앙상블 동기 세션

### 방 만들기

1. leader 이상 권한으로 `앙상블`을 엽니다.
2. 템포맵이 저장된 레퍼토리를 선택합니다.
3. 방을 만듭니다. 이때 사용할 템포맵 revision과 유효한 시작 마디·pass가 고정됩니다.
4. `초대 링크`로 링크를 복사해 공유합니다. 클립보드가 거부되면 화면에 표시되는 URL을 직접 선택해 복사합니다. 네이티브 앱에서도 다른 기기가 열 수 있는 공개 웹 주소를 공유합니다.

### 방 참가와 준비

1. 초대 링크를 열거나 방 ID를 입력합니다.
2. 로그인이 필요하면 로그인 후 원래 방으로 돌아옵니다.
3. 참가자 목록에서 이름, 역할, RTT, 보정, Bluetooth와 준비 상태를 확인합니다. 작은 화면에서는 `참가자`를 눌러 목록을 엽니다.
4. 자신의 `준비`를 켭니다. 이 클릭으로 소리 엔진을 먼저 준비한 뒤 준비 상태를 전송합니다. 소리 준비 자체는 클릭을 재생하지 않습니다. 무대의 준비 인원수와 각 참가자의 준비/대기 표시를 확인합니다.

이미 연주 중인 방에 들어와 `소리 켜고 합류`가 보이면 눌러 소리를 준비합니다. 소리 준비 전에는 `합류 대기`, 다음 마디의 소리를 예약한 뒤 첫 소리가 나기 전에는 `시작 대기`로 표시합니다. 시작할 마디의 BPM·박자를 확인할 수 있습니다.

### 시작·정지

- leader는 `재생 설정`에서 시작 마디, 반복 차수와 예비박을 정하고 무대에서 시작·정지합니다. `시작`을 누를 때도 해당 기기의 소리 준비를 먼저 완료합니다.
- member는 자신의 준비 상태를 바꾸고 리더가 제어하는 재생 상태를 확인합니다.
- 명령을 보낸 뒤 서버 확인 또는 timeout 전까지 같은 조작이 잠겨 중복 시작을 막습니다.
- 작은 화면에서는 박자·현재 마디와 준비·리더 시작/정지를 위쪽에 함께 표시합니다. 방 코드·고정 revision·RTT는 `연결 정보`를 펼쳐 확인합니다.
- 네트워크가 잠시 끊겨도 이미 예약된 로컬 클릭은 계속될 수 있습니다. 복구 후에는 다음 안전한 마디 경계에서 합류합니다.
- 권한 제거, 만료된 방, 다른 기기의 동일 계정 접속 같은 종료 사유는 무한 재연결하지 않고 화면에 상태를 표시합니다.

정확한 합주 기준은 실제 기기와 출력 장치에 영향을 받습니다. Bluetooth는 일반적으로 큰 지연이 있으므로 참가자 모두 내장 또는 유선 출력을 사용하는 편이 좋습니다.

### 악보를 보며 합주하기

방 안에서 `악보 보기`를 누르면 같은 세션의 재생을 유지하며 총보나 파트보를 볼 수 있습니다. `박자 크게`로 큰 박자 화면에 돌아옵니다. 악보를 스크롤해도 박자와 세션 조작은 상단에 남고, 가로 여유가 있으면 박과 조작을 2열로 보여 줍니다. 파트를 바꾸거나 악보를 탐색해도 방의 재생 위치는 바뀌지 않으며, 수동으로 다른 페이지를 본 뒤에는 `재생 위치로 돌아가기`로 자동 추적을 다시 켭니다.

방은 만들 때 선택된 템포맵 버전을 계속 사용합니다. 편집기에서 구간별 BPM·박자를 바꿔 저장했다면 새 방을 만들어 변경된 버전으로 함께 연습하세요.

## 9. 악보 사용법

### 악보 추가

지원 형식은 PDF, 일반 이미지, MusicXML/XML/MXL입니다.

1. 비로그인은 로컬 `악보`, 로그인 사용자는 레퍼토리의 `악보`를 엽니다.
2. `파일 선택`으로 악보를 고릅니다.
3. 프로젝트 악보는 leader 이상만 업로드할 수 있습니다.
4. 업로드가 완료돼 준비 상태가 된 악보만 목록에 표시됩니다.

MusicXML을 올리면 마디, 박자, 템포, 반복과 이동 지시를 분석한 템포맵 초안이 표시됩니다. 구간·jump·못갖춘마디와 경고를 검토한 뒤 `템포맵으로 저장`을 누르세요. 자동 분석 결과를 검토 없이 원본 악보의 절대 정답으로 간주하지 마세요.

### 총보와 파트보

- 악보 정보에서 `총보` 또는 `파트보`, 악기 이름을 지정합니다.
- 파트 탭을 선택하면 같은 곡의 현재 canonical 마디를 유지합니다.
- 파트의 인쇄 1마디가 곡의 11마디라면 공통 마디 번호 오프셋에 `10`을 입력합니다.

### 마디 매핑

PDF와 이미지는 페이지의 어느 위치가 어느 마디인지 직접 연결할 수 있습니다.

1. 도구에서 `마디 매핑`을 선택합니다.
2. 한 시스템 전체를 드래그합니다.
3. 각 마디 경계를 왼쪽부터 차례로 누릅니다.
4. 첫 마디 번호를 확인하고 `시스템 완료`를 누릅니다.
5. 키보드 사용자는 펼침 영역에서 마디 번호와 좌표 비율을 직접 입력할 수 있습니다.

매핑이 있으면 현재 마디 강조, 마디 선택, 파트 간 이동과 자동 페이지 추적을 사용할 수 있습니다. 업로드·마디 매핑·번호 보정은 leader 이상만 가능합니다.

OMR은 PDF·이미지를 읽어 이 마디 영역의 초안을 제안하는 선택 기능입니다. 자동 결과가 기존 매핑을 덮어쓰지는 않으며 사용자가 미리 본 뒤 저장해야 합니다. 현재 서버에서는 Audiveris OMR을 끈 상태이므로 위 수동 매핑을 사용하면 되고, OMR을 제공하기로 할 때만 서버 실행 환경과 정확도 검증이 필요합니다.

### 필기

도구에서 다음 중 하나를 선택합니다.

- `펜`: 악보 위를 그립니다. 필기 위치는 악보 안의 0–1 좌표로 저장하고, 선은 확대율과 관계없이 3 CSS px 두께로 표시합니다.
- `텍스트`: 내용을 입력하고 현재 마디 중앙 또는 페이지 위치에 둡니다.
- `기호`: 지정한 기호를 둡니다.
- `보기`: 필기하지 않고 악보를 탐색합니다.

필기 범위는 `나만 보기` 또는 `프로젝트 공유`로 고릅니다. 마디에 연결한 텍스트·기호는 다른 파트의 같은 canonical 마디 위치로 재투영될 수 있고, 페이지 좌표 필기는 원래 악보에만 표시됩니다. 이 페이지 필기 목록에서 작성 권한이 있는 필기를 삭제할 수 있습니다.

### 악보와 함께 재생

1. 로컬 PDF·이미지는 `저장한 템포맵 연결`에서 연습할 맵을 고릅니다. 맵이 없거나 구간을 바꾸려면 `구간 편집`을 눌러 구간별 BPM·박자를 저장한 뒤 `악보로 돌아가기`를 누릅니다.
2. 현재 마디를 선택하고 `재생`을 누릅니다. 멈추려면 같은 위치의 `정지`를 누릅니다.
3. 재생 카드의 박 표시·현재 마디·BPM·박자와 매핑된 악보 페이지가 연주 위치를 따라갑니다. 재생 중이며 `보기` 모드일 때는 스크롤해도 재생 카드가 상단에 남습니다. 정지하거나 마디 매핑·필기를 할 때는 카드도 본문과 함께 스크롤합니다. 템포맵 연결은 정지한 뒤 바꿀 수 있습니다.
4. 사용자가 직접 다른 페이지로 이동하면 자동 추적이 잠시 멈춥니다.
5. `재생 위치로 돌아가기`로 현재 연주 위치를 다시 따라갑니다.

화면 읽기 도구에서 `재생`/`정지`는 각각 `이 마디부터 재생`/`악보 재생 정지`, `구간 편집`은 `마디 구간 편집`으로 안내됩니다.

연결된 로컬 맵이 삭제되었거나 유효하지 않으면 다른 맵을 선택하라는 오류가 표시됩니다. 프로젝트 악보는 해당 곡의 템포맵을 사용하며 owner/leader가 `구간 편집`으로 수정합니다. 앙상블 방 안에서 연 악보의 재생은 위의 독립 재생 버튼 대신 세션의 준비·시작·정지 조작을 사용합니다.

## 10. 연습일지와 할일

### 연습일지

1. `연습`을 엽니다.
2. `오늘의 메모`에 Markdown으로 내용을 입력합니다.
3. 필요하면 `미리보기`로 표시 결과를 확인합니다.
4. 특정 위치와 연결하려면 마디 번호를 입력합니다.
5. `일지 저장`을 누릅니다.

마디가 연결된 일지에서는 `악보에서 보기`로 해당 위치를 열 수 있습니다. 일지를 삭제하면 연결된 할일도 함께 삭제되며 되돌릴 수 없습니다.

### 할일

1. 해당 일지의 할일 입력칸에 내용을 적습니다.
2. 선택적으로 담당자와 기한을 지정합니다.
3. 추가 버튼을 누릅니다.
4. 완료 여부를 체크해 갱신합니다.

멤버 정보를 불러오지 못하면 담당자를 지정할 수 없지만 할일 자체는 저장할 수 있습니다. 원격 오프라인 사본을 보는 동안 일지와 할일은 읽기 전용입니다.

## 11. 튜너와 출력 보정

### 튜너

1. `튜너`에서 `튜닝 시작`을 누릅니다.
2. 브라우저 또는 OS의 마이크 권한을 허용합니다.
3. 한 음을 안정적으로 연주합니다.
4. 음이름, 주파수, 명료도와 센트 편차를 확인합니다.
5. 오케스트라 기준에 맞게 A4를 415, 430, 440, 442 또는 443Hz로 선택합니다.
6. 끝나면 `마이크 끄기`를 누릅니다.

권한 대기 중 화면을 나가도 늦게 열린 마이크 스트림을 정리하도록 구현돼 있습니다. 오류가 나면 OS 사이트 권한을 허용하고 `다시 시도`를 누르세요.

### 출력 지연 보정

1. `출력 보정`에서 현재 출력 장치 이름을 확인하거나 입력합니다.
2. Bluetooth 자동 감지 결과를 확인합니다. 감지할 수 없으면 무선 출력 여부를 직접 선택합니다.
3. `측정 시작`을 누릅니다.
4. 클릭이 들리는 순간마다 큰 탭 버튼을 누릅니다.
5. 총 9번 탭합니다. 첫 표본은 적응용으로 제외하고 나머지 중앙값을 사용합니다.
6. 결과를 `이 장치에 저장`합니다.

양수 보정값은 클릭을 그만큼 앞당겨 예약합니다. 로그인 상태에서 서버 동기화에 성공하면 앙상블 세션에도 적용됩니다.

## 12. 설정

### 화면과 메트로놈

- 모바일 `더보기`의 테마 버튼 또는 데스크톱 상단 해/달 버튼: 어느 화면에서든 다크·라이트를 즉시 전환합니다.
- `다크`/`라이트`: 설정 화면에서 같은 테마 값을 명시적으로 선택합니다. 두 조작 모두 앱 본문과 고정 하단 UI, 브라우저/PWA theme color, 네이티브 system bar를 함께 바꾸고 현재 기기에 저장합니다.
- `예비박 마디`: 기본 예비박을 설정합니다.
- `볼륨`: 기본 클릭 음량을 저장합니다.
- `시각 오프셋`: -100ms에서 +100ms 사이로 박 표시만 앞당기거나 늦춥니다. 오디오 클릭 시점은 바뀌지 않습니다.

### 오프라인 저장 공간

지원 브라우저에서는 현재 사이트 데이터 사용량과 quota를 표시합니다. 브라우저가 Storage Estimate를 지원하지 않는 경우에는 기능 미지원 안내가 나옵니다. 사이트 데이터를 직접 지우면 비로그인 로컬 데이터도 함께 사라질 수 있습니다.

### 로그아웃

`로그아웃`은 현재 인증 세션을 제거합니다. 사용자별 원격 오프라인 사본은 다른 계정에 노출되지 않도록 계정 ID로 분리됩니다.

### 계정 삭제

1. `설정`의 계정 섹션에서 `계정 삭제`를 누릅니다.
2. 계정 이메일을 정확히 입력합니다.
3. 비밀번호 계정은 현재 비밀번호를 입력합니다.
4. Google-only 계정은 Google 재인증 또는 탈퇴 확인 이메일 링크로 본인을 확인합니다.
5. 네이티브 앱이나 Google 재인증을 사용할 수 없는 환경에서는 `탈퇴 확인 이메일 보내기`를 사용합니다.
6. 메일의 보안 링크를 같은 흐름에서 열고 삭제 화면으로 돌아옵니다.
7. 영향을 확인한 뒤 `계정 영구 삭제`를 누릅니다.

삭제하면 로그인 자격증명, 소유 그룹과 하위 프로젝트·레퍼토리·악보 원본, 개인 필기·일지·보정이 삭제됩니다. 다른 구성원이 사용하는 공유 감사 이력에는 식별 불가능한 삭제 사용자 표지만 남을 수 있습니다. 계정과 분리된 이 기기의 비로그인 로컬 연습 데이터는 자동 삭제되지 않습니다.

앱을 설치하지 않아도 공개 `/delete-account` 화면에서 삭제 절차를 시작할 수 있습니다. 비밀번호나 인증 토큰을 고객지원에 보내지 마세요.

## 13. 오프라인, PWA와 모바일

### 오프라인 동작 구분

| 데이터 | 오프라인 사용 | 오프라인 수정 |
| --- | --- | --- |
| 비로그인 로컬 템포맵·악보·필기 | 가능 | 가능 |
| 비로그인 로컬 연습일지 | 가능 | 가능 |
| 마지막으로 성공한 프로젝트 템포맵 | 가능 | 불가 |
| 마지막으로 성공한 프로젝트 악보·마디맵·필기 | 가능 | 불가 |
| 마지막으로 성공한 프로젝트 연습일지·할일 | 가능 | 불가 |
| 앙상블 방 생성·참가 | 불가 | 불가 |

프로젝트 사본은 실제 네트워크 실패에서만 표시됩니다. 401/403/404/409/422 또는 서버 오류는 오래된 사본으로 숨기지 않고 오류와 재시도를 보여 줍니다.

### PWA 설치

지원 브라우저의 `홈 화면에 추가` 또는 `앱 설치` 기능으로 설치할 수 있습니다. 앱 시작 시 과거 버전이 인증 API 응답을 잘못 캐시하지 않았는지 먼저 확인합니다. 안전하게 정리됐음을 확인할 수 없으면 본 앱 대신 `보안 업데이트를 완료하지 못했습니다` 화면과 재시도 버튼을 표시합니다.

### 모바일 앱

- 웹과 동일한 기능 화면을 사용합니다.
- 인증 정보는 iOS Keychain 또는 Android Keystore에 저장합니다.
- 재생 중 Keep Awake, 박 햅틱, 테마별 system bar를 네이티브 bridge로 연결합니다.
- 방 초대, 계정 생성 완료, 비밀번호 재설정, 탈퇴 확인의 허용된 딥 링크만 엽니다.
- Google 네이티브 로그인은 현재 지원하지 않습니다.

서명된 스토어 설치, iOS 무음 스위치·잠금·백그라운드, Android 제조사별 절전, 실제 Universal/App Link는 실제 배포와 기기에서 별도로 확인해야 합니다.

## 14. 문제 해결

| 증상 | 먼저 확인할 것 | 해결 방법 |
| --- | --- | --- |
| 앱 대신 보안 업데이트 오류가 표시됨 | 오래된 탭 또는 Service Worker | 다른 FeelMyRythm 탭을 닫고 `다시 확인`; 계속되면 브라우저의 사이트 데이터·Service Worker 상태 점검 |
| 인증 메일이 오지 않음 | 이메일 철자, 스팸함, 재전송 대기 | `인증 메일 다시 보내기`; 계속되면 운영자에게 발생 시각만 전달 |
| 로그인할 수 없음 | 이메일 확인 여부, 비밀번호 | 인증 완료 후 재시도하거나 비밀번호 재설정 사용 |
| Google 버튼이 없음 | 배포 OAuth 설정 또는 모바일 환경 | 웹은 해당 배포의 SSO/local 로그인 안내를 따름. production 모바일은 native SSO bridge 전까지 출시하지 않음 |
| 메트로놈 재생이 시작되지 않음 | 템포맵 loading/error, 브라우저 오디오 권한 | 화면의 `다시 시도`; 사용자 조작 후 재생 버튼 다시 누르기 |
| 프로젝트 사본이 읽기 전용임 | 네트워크 단절 상태 | 연결 복구 후 `서버 다시 확인` 또는 화면의 재시도 사용 |
| 방에 참가할 수 없음 | 로그인, 그룹 멤버십, 방 만료, 동일 계정의 다른 연결 | 올바른 계정과 멤버십 확인 후 새 초대 링크 요청 |
| 합주 클릭이 어긋남 | Bluetooth, 보정 미완료, 큰 RTT | 유선/내장 출력 사용, 각 기기 출력 보정, Wi-Fi 상태 확인 |
| 초대 링크 복사가 안 됨 | Clipboard 권한 | 화면의 읽기 전용 URL을 직접 선택해 복사 |
| 악보가 열리지 않음 | 형식, 네트워크, 큰 파일 | PDF·이미지·MusicXML 형식 확인 후 `다시 시도`; leader는 다시 업로드 |
| 마디 강조 위치가 틀림 | MeasureMap, 파트 offset | leader가 마디 매핑과 공통 마디 번호 오프셋 수정 |
| 튜너가 음을 읽지 못함 | 마이크 권한, 주변 소음, 화음 | 권한 허용 후 단음을 가까이서 안정적으로 연주 |
| 저장 공간을 확인할 수 없음 | 브라우저 API 지원 여부 | 기능 미지원이면 브라우저 설정에서 사이트 데이터 직접 확인 |

## 15. 중요한 제한과 안전 수칙

- 서버 beat 스트리밍이 아니라 각 기기의 오디오 클럭을 사용하므로 실제 출력 지연 보정이 중요합니다.
- Bluetooth를 제외한 기기 간 ±10ms 목표는 실제 여러 기기 녹음으로 검증해야 하며 코드 구현만으로 보장되지 않습니다.
- MusicXML 초안은 원본 표기의 자동 해석 결과입니다. 저장 전에 반복·볼타·Fine/Coda와 못갖춘마디를 검토하세요.
- 비로그인 로컬 데이터는 서버 계정과 별개입니다. 사이트 데이터 삭제, 앱 제거 또는 기기 손실에 대비해 중요한 템포맵을 내보내세요.
- 계정 삭제와 그룹·악보 삭제는 되돌릴 수 없습니다. 삭제 확인 문구에서 영향을 다시 확인하세요.
- 비밀번호, 메일 링크의 token, 계정 삭제 proof, JWT나 S3 자격증명을 다른 사람에게 보내지 마세요.
- 실제 iOS·Android 출시 상태, 선택한 SMTP·S3 provider와 DB/volume 보존 상태는 [기능 카탈로그의 외부 검증 항목](./FEATURES.md#12-아직-완료-기능으로-세지-않는-경계)과 [운영 준비 및 검증 절차](./OPERATIONS.md)를 기준으로 확인하세요.
