# FeelMyRythm UI 디자인 시스템

폭·높이·화면 방향·포인터·safe area·글자 확대에 따른 구체적인 재배치는
[RESPONSIVE_UX.md](./RESPONSIVE_UX.md)를 함께 따른다.

디자인 목표: **깔끔하고, 고급스럽고, 한눈에 읽히는** 인터페이스.

- 함께 볼 문서: [설계문서](./DESIGN.md) — 특히 §9 박자 시각화(공학심리학 근거)는 이 문서의 상위 제약이다.
- 구현: Tailwind CSS 4 (CSS 변수 토큰) + Radix UI 프리미티브 + lucide 아이콘

---

## 1. 디자인 방향

**"무대 위의 악기처럼"** — 장식이 아니라 마감 품질로 고급스러움을 낸다.

1. **다크 기본**: 연습실·무대·보면대 환경은 어둡다. 어두운 배경은 박 플래시의 대비를 극대화하고(§9 시인성), OLED 기기에서 전력도 아낀다. 라이트 모드도 같은 토큰 계약으로 지원한다.
2. **채도 절제 + 단일 포인트 컬러**: 무채색에 가까운 어두운 표면 위에 **골드 하나만** 포인트로 쓴다. 색이 적을수록 "지금 중요한 것"(현재 박, 다운비트)이 즉시 눈에 들어온다.
3. **숫자가 주인공**: 이 앱의 1급 정보는 BPM·마디 번호·박자표다. 큰 사이즈와 멀리서도 끊기지 않는 regular 계열 굵기로 위계를 만든다.
4. **연습 중 조작 최우선**: 악기를 든 채로 조작한다. 큰 터치 타깃, 한 손 도달 범위(모바일 하단), 실수해도 되돌리기 쉬운 조작.
5. **여백이 고급스러움을 만든다**: 요소를 줄이고 간격을 넉넉히. 정보 밀도가 필요한 곳(편집기·대시보드)만 컴팩트 스케일 사용.

규칙:

- 골드는 화면당 1–2곳만. 골드가 흔해지면 다운비트 강조가 죽는다.
- 상태색(danger/success/info)은 아이콘·라벨과 병용 — 색 단독 의미 전달 금지 (색각이상 대응, §9와 동일 원칙).
- 박 원 시각화 색은 위 토큰 고정: 다운비트=골드, 일반박=아이보리, 분할박=회색, 예비박=세이지.

### 2.2 라이트

종이 느낌의 웜 화이트 기조: `--bg #FAF8F3`, `--surface #FFFFFF`, `--text #1C1A15`, `--text-muted #706B62`, `--control-border #8C867A`. 골드는 작은 텍스트와 흰색 버튼 라벨 모두 4.5:1 이상을 확보하도록 `--accent #916C24`, `--accent-hover #7D5917`을 쓴다. muted text도 raised surface까지 4.5:1 이상을 유지한다. 토큰 이름은 동일하므로 CSS 변수 스위칭만으로 전환한다.

## 3. 타이포그래피

| 용도 | 스펙 |
|---|---|
| 기본 서체 | **Pretendard Variable** (한글·라틴 통합, 웹폰트 subset) |
| 숫자 표시 전반 | `font-variant-numeric: tabular-nums` **필수** — BPM·마디·타이머가 바뀔 때 폭이 흔들리면 싸 보이고 읽기 어렵다 |
| BPM 디스플레이 | 64–128px, weight 400 (큰 크기와 regular 획으로 원거리에서 끊기지 않게 유지) |
| 마디/카운트다운 | 48–64px, weight 300 |
| 페이지 제목 | 24px / 600 |
| 섹션 제목 | 18px / 600 |
| 본문 | 15px / 400, 행간 1.6 |
| 캡션·라벨 | 13px / 500, `--text-secondary`, 자간 +0.02em |

- 디스플레이 숫자는 300–400, 일반 UI는 400–600 범위로 제한한다. 장식적인 굵기 변화를 늘리지 않는다.
- 기존 beats variant의 예비박 카운트다운은 가용 canvas 높이의 약 62%를 쓰되 24–160px
  안에서 clamp한다. 모바일의 큰 박 숫자는 실제 glyph로 계산한 fit 글자 크기의
  80%를 쓰며 panel 크기·배치와 200px 상한 없는 fit 계산을 유지한다. 박자표는 원형 박 아래 속도 숫자 옆에 둔다
  (§9: 원거리 시인성).

## 4. 레이아웃 · 간격 · 형태

- **4px 그리드**: 간격은 4의 배수만 (8/12/16/24/32/48).
- **라운딩**: 카드 16px, 버튼·입력 10px, 풀스크린 시트 24px. 원형은 재생/탭템포 버튼에만.
- **그림자 대신 표면 밝기 차**로 깊이 표현 (다크에서 그림자는 안 보임). 라이트 모드에서만 은은한 그림자.
- **최대 폭**: 콘텐츠 페이지 720px, 대시보드 1200px. 메트로놈 메인은 뷰포트 전체 사용.
- 모바일: 주요 조작(재생·정지·탭템포)은 하단 30% 영역에. 상단은 표시 전용.

## 7. 화면별 레이아웃 가이드

### 7.1 메트로놈 메인 (가장 중요한 화면)

데스크톱 기본 구조의 정보 위계:

```
┌─────────────────────────────┐
│  곡 제목 · 구간 라벨(A, ♩=100)      │  ← 캡션 크기
│                             │
│   ●  ○  ○  ○                │  ← 박 슬롯 (화면 폭의 70%)
│   [채움 예측 큐 링/바]           │
│                             │
│         100                 │  ← BPM (가늘고 크게)
│         BPM · 4/4           │
│      마디 26 · 다음: 3마디 뒤 ♩=130│  ← 상황 인식(§9)
│                             │
│   [탭템포]   (▶)   [구간설정]     │  ← 하단 조작 영역
└─────────────────────────────┘
```

- 일반 모바일 화면(폭 839px 이하)은 단일 `.performance-context` DOM으로 현재 마디·시작 대기·예비박 상태를 상단 header 왼쪽에 표시한다. 예비박에도 `마디 1 · 예비박 4`처럼 마디를 유지하며 다음 구간이 없으면 모바일 `다음: 마지막 구간`은 생략한다. 기존 개인 연습/Section 문맥은 숨기되 접근 가능한 `h1`은 유지하고 desktop/fullscreen은 기존 stage 문맥을 유지한다. 모바일 stage는 큰 박 번호 → 원형 박 → 현재 속도 숫자와 박자표 순으로 표시한다. 속도 옆 `BPM` 글자는 숨기며 박자표는 속도 숫자 옆에 둔다. 양쪽이 같은 폭인 grid로 속도 숫자의 중심을 고정하고 오른쪽 박자표와 baseline을 맞춘다. 원형 박 위에 `.metronome-number`를 둔다. 큰 박 숫자 영역은 테두리·둥근 모서리와 박자표 없이 번호만 중앙에 표시한다. 실제 glyph로 계산한 기존 fit 글자 크기의 80%를 적용하며 panel 크기와 배치는 유지한다. 본박 숫자는 `1..beatCount`의 최대 실측 폭을 기준으로 글꼴 크기를 고정하고 x 중심을 유지해 박마다 크기·위치가 흔들리지 않게 한다. 같은 오디오 frame source의 rAF로 현재 본박 번호를 표시하고 예비박은 countdown, 예약 대기는 `—`로 바꾼다. 숫자는 테마 text 단색을 유지하고 오디오 progress에 따라 opacity 0.6–1로 pulse한다. 본박/예비박 경계마다 반복하되 subdivision에는 다시 시작하지 않으며 화면 전체를 점멸하지 않는다. 정지 중에는 숫자를 고정하며 reduced motion에서는 pulse 없이 실제 박 번호만 갱신한다. 모바일 일반 메트로놈의 진행 배경은 오디오 `frame.progress`에 따라 하단 메뉴 위까지의 앱 영역을 가장 낮은 배경 레이어에서 진한 주황 `#f47a24`, opacity 0.3으로 왼쪽에서 오른쪽으로 채운다. 600–839px 가로 화면에서는 왼쪽 rail을 제외하며 메뉴는 원래 표면을 유지한다. 큰 숫자 영역에는 별도 배경 채움을 두지 않고 숫자의 pulse·fit 계산을 유지한다. 정지·예약 대기·reduced motion에서는 채움을 비우며 route 이탈·desktop·fullscreen 전환 때 장식 레이어를 제거한다. 모바일의 기존 radial 배경 반응은 끄고 원형 canvas에도 bar를 중복하지 않는다. 기본 bar·desktop/fullscreen·다른 BeatVisualizer 사용처는 기존 bar와 reduced-motion 고정 track을 유지한다. 진행 전용 `BeatVisualizer`의 `variant="progress"`를 Page 내부에 fixed로 렌더하고 활성 `.app-shell`의 `isolation: isolate` 안에서 `z-index: -1`로 앱 표면 바탕 위·모든 콘텐츠 아래에 둔다. `pointer-events: none`·`aria-hidden`으로 장식만 제공한다. 상속된 `--mobile-nav-height`만큼 bottom을 제외하며 600–839px landscape는 `--rail-width`만큼 left를 제외하고 bottom은 0으로 둔다. 내비게이션의 기존 배경은 유지한다.
- 모바일 상단의 보면대 버튼은 제거하고 큰 박 번호를 누르면 인앱 집중 화면을 토글한다. 집중 화면은 메뉴를 숨기므로 진행 배경의 inset을 0으로 두되 콘텐츠 아래 레이어는 유지한다. 집중 화면에는 큰 번호·원형 박·속도/박자표·재생/정지만 남기고 상단·하단 메뉴, ±5·탭·설정을 숨긴다. 다시 큰 번호를 누르거나 입력 dialog가 닫힌 상태에서 Escape로 복귀하며 오디오 재생은 유지한다. 데스크톱의 기존 fullscreen 동작은 유지한다. 모바일 일반 화면의 세부 설정은 테두리 없는 아이콘만 표시하며 44px, coarse pointer에서는 48px의 터치 영역과 `세부 설정` 접근성 이름을 유지한다. 모바일에서는 속도 숫자를 눌러 기존 20–400 입력 dialog를 열고, 박자표를 눌러 2/4·3/4·4/4·5/4·6/8·9/8·12/8의 같은 7개 선택지를 가진 dialog를 연다. 박자표 변경 시 기존 앞 박 강세를 보존하고 초과분은 제거하며 추가 박은 보통 강세로 채운다.
- 데스크톱 풀스크린 모드(보면대): 기존 visualizer를 유지한다. 나가기와 재생 안전 조작을 제외한 BPM 편집·템포맵 편집·설정·문맥 UI를 `inert`/`aria-hidden`으로 포커스에서 제외한다. fullscreen 뒤의 AppShell topbar·sidebar·bottom navigation도 같은 방식으로 제외한다. 설정 panel과 보조 조작은 grid flow에서도 제거하고, 템포맵 상태가 있으면 별도 row를 사용해 stage가 계속 남는 높이를 받도록 한다. 일반 화면의 compact/medium 다열 grid와 카드 모서리를 상속하지 않고 `border-radius: 0`의 단일 열 edge-to-edge 표면으로 재설정해 모든 폭에서 재생 버튼을 중앙에 둔다. 박 슬롯+BPM+마디 번호와 재생 중에만 나타나는 은은한 배경 반응에 집중한다.
- 예약 대기·예비박의 마디·BPM·박자 문맥은 최종 재생 anchor를 사용한다. 첫 오디오 전의 `시작 대기`에서는 박 강조·접근성 announcement·반응 배경을 시작하지 않는다.
- 예비박 중에는 일반 박 원 없이 대형 카운트다운 숫자를 표시한다. desktop/fullscreen 배경은 기존 `--count-in` 톤을 유지하고 모바일 일반 화면은 메뉴를 제외한 가장 낮은 배경 레이어의 주황 진행 채움을 사용한다. 숫자는 canvas 안으로 제한하며 기본 bar 사용처는 reduced motion에서도 고정 track을 유지한다.
- 진행막대가 없는 원형 박 묶음은 canvas의 가로·세로 중앙에 정렬한다. 박 슬롯 canvas는 CSS 표시 크기와 device pixel ratio에 backing store를 맞춘다. 모바일 큰 숫자 canvas는 최소 높이 56px의 relative wrapper 안에 `position: absolute; inset: 0`으로 맞춰 backing store의 intrinsic 높이가 grid의 `min-content` 계산에 다시 들어가지 않게 한다. 재생 중 rAF뿐 아니라 정지 상태의 element resize와 테마 변경에도 다시 그려, 창을 좁힌 직후 늘어난 원이 남지 않게 한다.
- 가용 높이가 커지면 기본·비활성 박 반지름은 최대 72px, 현재 일반박은 최대 79px, 현재 다운비트는 최대 82px, 진행 track은 최대 14px까지 보간하고 canvas 높이도 함께 늘린다. 가용 폭에 들어오는 일반 박자에서는 각 고정 슬롯에 번호를 표시하고, 고박자에서는 현재 박을 포함한 번호 window와 생략 표시로 전환해 원을 판독 불가능하게 줄이거나 자르지 않는다. 현재 박은 색·윤곽·크기를 함께 바꿔 색 하나에 의존하지 않는다. desktop의 기존 박 canvas는 `clamp(180px, 28dvh, 340px)`, Wide에서는 최대 380px 범위를 유지한다. 폭 599px 이하 일반 모바일 page는 본문 가용 높이를 채우고 header·원형 박·속도·박자표·controls·상태 영역을 제외한 남는 높이를 숫자 panel에 배분한다. 모바일 마디 문맥은 header에, desktop/fullscreen 마디 문맥은 stage에 둔다. 짧은 화면·200% 확대에서는 내용 안전 최소 높이와 세로 스크롤을 사용한다.
- 폭 599px 이하·높이 900px 이하에서는 설정을 sheet로 보낸다. 모바일 일반 화면의 원형 박 canvas는 숫자 panel 아래 별도 row에서 `clamp(64px, 10dvh, 92px)` 높이를 쓴다. 599px 이하 page는 `height: 100%`와 `min-content`를 최소 높이로 삼는 가변 stage row를 쓰며 숫자 panel이 남는 높이를 채운다. 600–839px 숫자 panel은 `clamp(128px, 38dvh, 480px)`, 높이 700px 이하에서는 `clamp(80px, calc(100dvh - 200px), 240px)`로 조정한다. `600–839px`은 모든 높이에서 stage와 조작을 2열로 나누고, 높이 820px 이하에서는 설정 sheet를 쓰며 821px부터 인라인 설정과 빠른 `시작 마디`를 복원한다. 840px 이상은 높이 640px까지 stage와 조작을 2열로 나누고 820px 이하에서 canvas와 BPM을 먼저 축소한다. 모바일 stage는 숫자 panel → 원형 박 → 속도·박자표를 세로의 일반 흐름으로 둔다. 숫자 panel의 204/116/52px 고정 높이와 recovery의 원형 박·BPM 병렬 배치는 사용하지 않는다. 현재 마디·대기·예비박은 header에 유지하며 짧은 화면·200% 확대에서는 최소 높이와 세로 스크롤로 내용·48px 조작이 겹치지 않게 한다. Fullscreen은 모든 폭의 높이 640px 이하에서 전용 축소를 사용하고 320px 이하에서는 세로 스크롤 안전 경로로 바꾼다. 폭 839px 이하 일반 화면(집중 화면·fullscreen 제외)은 한 줄 중앙에 `−5 → 재생/정지 → +5`를 묶고 `탭`을 오른쪽 끝에 작고 은은한 글자로 표시한다. Medium의 stage/조작 2열 외곽 틀과 세로 여유가 있는 Medium·긴 phone의 빠른 시작 마디 field는 유지한다. 예비박 토글은 모든 폭의 메인 controls에서 제거해 세부 설정 dialog/인라인 panel의 공용 `settingsControls`에 넣고 기존 저장 동작을 유지한다. 모바일 한 줄의 시각·키보드 DOM 순서는 `−5 → 재생/정지 → +5 → 탭`으로 일치시킨다. 일반 Expanded/Desktop은 재생을 중앙에 두기 위해 시각적으로 BPM 조절 → 재생 → 빠른 설정을 쓰되 DOM/포커스는 재생 우선을 유지한다. 모바일 `탭` 글자는 좁은 화면에서도 유지하고 접근성 이름은 `탭 템포`다. 데스크톱은 `탭 템포` 버튼의 직접 측정을 유지한다. 첫 탭 뒤에는 `다시 탭`, 이후에는 누적 횟수를 시각 라벨과 별도 polite status에 잠시 표시해 같은 feedback을 전달한다. coarse pointer의 256px 배치에서도 한 줄의 −5·재생/정지·+5·탭 target을 유지하며, 필요한 간격을 줄여 핵심 target과 상태 복구 버튼을 48×48px 미만으로 줄이지 않는다. 설정의 예비박 버튼은 이름과 `켬`/`끔`을 글자로 보존한다. 숨겨진 빠른 시작 마디는 설정 sheet 안에 같은 field로 제공한다. sheet가 열린 동안 `820→821` 또는 `900→901` 경계를 넘어 trigger가 숨으면 닫을 때 새로 보이는 인라인 시작 마디로 focus를 복원하고, 동등 조작이 없으면 page heading으로 보낸다. BPM 단계 버튼은 20/400에서 해당 방향을 비활성화하고 ±5가 경계를 넘으면 끝값으로 clamp한다. 메트로놈에서 박자표를 바꾸면 기존 강세를 앞 박부터 보존하고 새 박수에 맞춰 초과분을 잘라내거나 추가 박을 보통 강세로 채운다. 강세는 무음·보통·강박 순환과 다음 상태를 이름으로 알리고 예비박은 색과 식별자·`켬`/`끔`을 함께 쓴다. BPM 직접 입력 dialog는 200% 확대의 `256 × 480`에서도 최초 input과 focus ring을 scrollport 안으로 이동한다. AppShell은 내비게이션 row를 본문 밖에 예약하고 확대된 하단 탭 높이를 Compact 96px·Micro 88px 이하로 제한하며, 본문의 24px scroll padding으로 재생·탭·시작 마디가 focus될 때 내비게이션 위에 완전히 나타나게 한다.
- 모바일 `탭`은 조작 영역 전체를 큰 탭 입력판으로 바꾸며 버튼을 여는 동작만으로 BPM을 변경하지 않는다. 입력판은 전체 화면 modal이 아니고 첫 탭을 기준 시각으로 삼아 실제 입력 간격으로 기존 탭 템포 계산을 수행한다. 열기·닫기는 측정에 포함하지 않고 매 진입 새 측정을 시작한다. 입력판은 최소 높이 128px이며 우상단 × 아이콘은 16px, touch target은 48px이다. × 또는 Escape로 원래 조작을 복원하고 탭 버튼에 focus를 돌린다. 폭 840px 이상 전환 시 입력판을 닫아 데스크톱 직접 탭으로 돌아가며 fullscreen 진입 시에도 측정을 초기화한다. 데스크톱 직접 탭과 보면대 모드는 유지한다.
- desktop/fullscreen의 재생 배경은 마디당 한 번인 다운비트에서만 저채도 radial glow로 반응하고 예비박은 하나의 연속된 낮은 채도 상태로 표시한다. 일반박마다 배경을 바꾸지 않아 빠른 BPM에서도 고빈도 flash를 만들지 않는다. 원·진행 바·마디 텍스트가 주 신호이고, `prefers-reduced-motion`에서는 fullscreen을 포함해 이 장식 배경 반응을 완전히 끈다.

- 모바일 일반 조작은 재생과 좌우 ±5의 묶음을 조작 영역 중앙에 두며 오른쪽 탭의 폭이 중심을 밀지 않게 한다. ±5와 탭의 네모 테두리·배경은 없애고 탭은 0.6875rem의 muted text로 작고 은은하게 표시한다. 48×48px 이상의 터치 영역과 키보드 focus는 유지한다. 큰 숫자 패널과 열린 탭 입력판의 외곽선은 유지한다.

### 7.2 템포맵 편집기

- 상단: 마디 눈금 타임라인 (구간을 색 블록으로, 반복은 위쪽 아치로 표시). 가로 스크롤+줌.
- 하단: 선택된 구간의 속성 패널 (박자표·BPM·강세·분할). 표 편집 뷰 토글.
- 표 뷰는 native `table`과 column/row header를 사용해 화면 읽기 도구에서 구간·마디·박자·BPM의 관계를 보존한다.
- 전개 미리보기: "연주 순서로 펼치면 총 ○마디 · ○분 ○초" 상시 표시 (반복 오류 즉시 발견).
- owner/leader가 새 원격 곡을 열면 저장 이력이 없는 경우에만 첫 초안을 제공한다. member는 기존 맵을 읽기 전용으로 보고 수정은 리더에게 요청한다. 로컬 맵은 로그인 중에도 같은 로컬 대상을 유지한다.
- 저장 후 `메트로놈에서 열기`로 그 맵을 재생하고, 악보에서 왔다면 `악보로 돌아가기`를 제공한다. 미저장 변경은 기존 저장·이탈 선택으로 보호한다.
- 원격 템포맵을 network failure 후 현재 계정의 IndexedDB v3 snapshot으로 열면 명시적인 “오프라인 읽기 전용” 상태와 연결 재확인을 노출한다. 편집·가져오기·저장은 잠그고 내보내기는 유지한다.

### 7.3 동기 세션(앙상블) 룸

- 무대의 정보 위계는 박자 → 현재 마디·BPM·박자표 → 준비·리더 시작/정지다. 작은 화면에서는 이 조작을 stage의 일반 문서 흐름에 함께 두며 고정 하단 bar로 겹치지 않게 한다. 짧은 가로 화면은 박과 조작을 2열로 나눈다.
- 참가자 항목은 이름·역할·연결 품질(RTT)·보정·Bluetooth와 준비/대기 상태를 보이며 무대에도 준비 인원수를 표시한다. 작은 화면의 목록은 `참가자` dialog로 연다.
- 리더의 시작 마디·반복 차수·예비박은 `재생 설정` dialog에서 바꾸고, 방 코드·고정 revision·RTT·무선 출력 안내는 접는 연결 정보에 둔다.
- 준비 켜기와 리더 시작은 사용자 클릭에서 오디오를 먼저 준비한다. 진행 중인 방에 아직 준비하지 않은 참가자는 `소리 켜고 합류`를 누른다. 미준비 상태는 `합류 대기`, 예약 뒤 첫 오디오 전은 `시작 대기`, 예비박 동안에는 카운트다운을 표시한다.
- `악보 보기`/`박자 크게`는 세션 route와 오디오를 유지한 채 보기만 전환한다. 악보는 고정된 방 revision과 외부 재생 위치를 받아 파트·페이지를 표시한다. 악보 보기의 박·조작은 스크롤 중 상단 sticky로 유지하며 폭 520px 이상에서는 압축된 2열을 사용한다.
- ready·시작·정지를 보낸 뒤 roster/transport acknowledgment 또는 5초 timeout이 오기 전에는 관련 조작을 pending으로 잠가 중복 클릭을 받지 않는다.
- 초대 URL은 브라우저의 현재 origin 또는 native의 공개 서버 origin을 사용한다. Clipboard API가 없거나 권한이 거부되면 선택 가능한 read-only input과 재시도 버튼을 제공한다.

### 7.4 악보 뷰어

- 독립 악보 화면은 곡/파트 전환과 재생 카드를 악보 위에 두고, compact 필기·매핑 도구는 `top: auto`로 상단 위치를 해제해 safe area를 고려한 **fixed bottom overlay**로 띄운다. 세션 안의 악보 도구는 일반 문서 흐름에 두고 세션의 박·조작과 공간을 공유한다.
- 독립 재생 카드는 재생 중이며 보기 모드일 때만 상단 sticky를 적용하고 정지·매핑·필기 중에는 일반 흐름에 둔다. 폭 600px 이상은 2열로 압축하고 재생 중에는 변경할 수 없는 템포맵 연결 상세를 숨긴다. 현재 마디·BPM·박자·박과 짧은 `재생`/`정지`, `구간 편집` 라벨을 표시하되 접근성 이름은 각각 `이 마디부터 재생`/`악보 재생 정지`, `마디 구간 편집`으로 유지한다. 로컬 PDF·이미지는 저장한 맵을 선택해 연결할 수 있으며 첫 편집은 맵 생성·연결 후 편집기로 이동한다. 세션 안에서는 방의 외부 transport만 표시한다.
- 현재 마디 하이라이트는 골드 20% 투명 사각형. 페이지 자동 넘김은 마디 진행 기준.
- 파트보 전환: 상단 세그먼트 컨트롤 (총보 | Vn1 | Vc | …), 전환 시 같은 마디 유지.
- 파트보 전환은 시각적 세그먼트와 함께 `tablist`/`tab`/`tabpanel`, roving tab index, 화살표·Home·End 키를 제공한다.
- 확대/축소는 score page surface 전체에 적용한다. 마디·page anchor 좌표는 surface 내부 0–1 값이므로 zoom 전후 같은 악보 위치를 가리켜야 한다. 펜의 저장 좌표도 0–1이며 표시 두께는 `non-scaling-stroke`로 zoom과 무관한 3 CSS px를 유지한다.
- 재생 중 이전/다음 페이지를 수동 선택하면 자동 페이지 추적을 일시 중지하고, **“재생 위치로 돌아가기”** CTA를 노출한다. CTA는 현재 마디 페이지로 이동한 뒤 auto-follow를 재개한다.
- measure anchor 주석은 파트 전환 뒤 대상 악보의 같은 canonical 마디에 표시한다. page anchor는 생성된 score/page에만 표시한다.
- 펜·시스템 매핑 시 pointer capture한 현재 `pointerId`만 move/up에 반영한다. stylus 스트로크 중 다른 손가락이 닿아도 섞지 않아야 하며 `pointercancel`은 임시 입력을 버린다.
- `/repertoire/:id/access`가 `member`이면 upload·악보 정보·마디 매핑 편집 조작을 노출하지 않거나 명확히 비활성화한다. 서버 오류는 캐시 화면으로 바꾸지 않고 원인을 표시하며, 실제 network fallback에는 현재 계정의 schema v3 snapshot만 사용해 “오프라인 읽기 전용” 상태를 표시한다.

### 7.5 그룹/프로젝트 대시보드

- 프로젝트 → 레파토리 카드 그리드 (곡명·템포맵 유무·악보 수·미완료 할일 수).
- 연습일지·할일은 카드 내 요약 + 상세 페이지.
- `/groups` 루트 실패는 전체 오류로 표시하되, members·projects·repertoire leaf 중 일부만 실패하면 동시 요청 6개 상한 안에서 성공한 카드를 계속 보여 주고 누락 개수·영역·재시도를 안내한다.

### 7.6 앱 셀·설치 표면

- 본문 scroller는 history entry별 좌표를 기억해 뒤로/앞으로 탐색에서 복원하고, 새 페이지는 맨 위와 `h1` focus에서 시작한다. browser POP은 모바일 더보기 overlay를 닫아 뒤 화면을 가리지 않는다.
- 폭 839px 이하 AppShell은 topbar를 제거하고 Bonifacio 복귀·테마·설정·계정/로그인·managed SSO 운영 안내를 하단 `더보기`에 둔다. 본문에는 상단 safe area를 보존한다. 폭 840px 이상은 topbar를 유지한다. 브라우저의 `← Bonifacio` 링크는 이 topbar와 모바일 `더보기`에서 최소 44px, coarse pointer에서는 48px을 확보하며 같은 탭에서 포트폴리오 홈으로 돌아간다. lazy route loading fallback은 AppShell 내부 본문에만 표시해 링크와 내비게이션을 유지하고, 준비된 새 화면의 `h1`으로 focus를 옮긴다. Capacitor 네이티브 shell에는 링크를 표시하지 않는다.
- PWA는 별도의 `any` 192/512px·`maskable` 512px PNG와 180px Apple touch icon, 고정 app `id`·scope·start URL, 한국어·category metadata를 제공한다.
- 테마는 모바일 `더보기`, 폭 840px 이상 topbar의 44px 이상 해/달 버튼과 설정 radiogroup에서 바꿀 수 있다. 모든 경로는 `data-theme`뿐 아니라 고정 하단 UI, browser/PWA `theme-color`와 Capacitor SystemBars 스타일까지 같이 바꾼다. storage·native API 실패는 새 테마의 웹 표시를 되돌리지 않는다.

## 8. 접근성 기준

- 자동 검증 대상인 primary/secondary/muted text의 실제 background/surface/surface-raised 조합과 accent의 background/surface 조합은 대비 4.5:1 이상을 유지한다. 입력·보조 버튼·비활성 박 윤곽은 인접 표면 대비, 고정 progress track은 background 대비 3:1 이상이다. 강조 배경 위 글자는 테마별 `--on-accent` 쌍을 사용한다.
- 모든 인터랙션 키보드 도달 가능 (Radix 프리미티브가 기본 보장).
- 터치 타깃 최소 44×44px, `any-pointer: coarse`인 혼합 입력 기기의 핵심 타겟은 48×48px.
- 박 정보는 시각(플래시)+청각(클릭)+촉각(모바일 햅틱) 3채널 중복 — 단일 감각 의존 금지.
- 시스템 폰트 크기 설정 존중 (rem 기반).

## 9. 구현 메모

- 토큰은 `packages/ui/tokens.css`에 CSS 변수로 정의, Tailwind 4 `@theme`으로 연결. 컴포넌트는 `packages/ui`에서 웹·모바일(Capacitor) 공용.
- 박 시각화 컴포넌트만 예외적으로 canvas/rAF 직접 렌더 (나머지는 일반 React).
- 다크/라이트는 중앙 theme helper가 `data-theme`, `meta[name="theme-color"]`, 저장소, Capacitor SystemBars를 동기화한다. 기본 다크.

## 10. 외부 UI 조사와 채택 범위

- [freesourc.es Color](https://freesourc.es/Color)와 [Development](https://freesourc.es/Development)는 원 출처를 찾는 인덱스로만 사용한다. 인덱스가 개별 자산의 재배포 권한을 보증하지 않으므로 화면·팔레트·일러스트를 복제하지 않는다.
- Happy Hues에서는 배경·본문·버튼·버튼 위 글자를 의미별로 분리하는 방식만 참고했다. 기존의 따뜻한 무대 테마와 semantic token 구조를 유지하고, 검증된 대비 값만 직접 토큰에 반영했다.
- Material의 adaptive layout 원칙처럼 기기 이름이 아니라 실제 폭과 높이를 독립 입력으로 사용한다. 새 Material Web 패키지는 기존 React·Radix 경계와 중복되므로 추가하지 않는다.
- 아이콘은 기존 ISC 라이선스의 Lucide named import를 계속 사용한다. Tabler·Feather·Phosphor 같은 두 번째 아이콘 체계, 한글을 포괄하지 않는 추가 웹폰트, 박 신호의 figure-ground를 약하게 만드는 배경 패턴은 도입하지 않는다.
- 최종 판정 기준은 [WCAG 2.2 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum), [비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast), [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [Apple UI Design Dos and Don'ts](https://developer.apple.com/design/tips/)다.
