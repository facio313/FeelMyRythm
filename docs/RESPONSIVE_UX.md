# FeelMyRythm 반응형·적응형 UX 명세

이 문서는 [UI_DESIGN.md](./UI_DESIGN.md)의 시각 원칙을 실제 화면 크기, 입력 방식,
접근성 설정에 적용하는 구현 계약이다. 화면을 특정 기기 이름에 맞추지 않고 **가용 폭,
가용 높이, 포인터 정밀도, safe area, 사용자 글자 크기**에 따라 적응시킨다.

## 1. 공통 불변 조건

- 페이지 자체에는 가로 스크롤이 생기지 않는다. 마디 타임라인, 악보 캔버스, 데이터 표처럼
  본질적으로 넓은 콘텐츠만 자체 스크롤 영역을 가진다.
- 주요 조작은 최소 `44 × 44px`, `any-pointer: coarse`인 혼합 입력 기기에서는 `48 × 48px`을 확보한다.
- 모든 페이지는 `100dvh`와 safe-area inset을 사용한다. 고정 하단 내비게이션과 토스트는
  `env(safe-area-inset-bottom)`을 포함한다. 폭 839px 이하에서 topbar를 제거해도 본문에는
  `env(safe-area-inset-top)`을 보존한다.
- 200% 글자 확대에서도 조작과 본문이 겹치거나 잘리지 않는다. 버튼 라벨은 두 줄까지
  허용하고, 행 기반 폼은 한 열로 재배치한다. Modal의 최초 focus는 확대 후에도 dialog의
  실제 scrollport 안에 완전히 들어오도록 이동한다. 짧은 화면에 모든 메트로놈 조작이 동시에
  들어오지 않으면 재생·탭·시작 마디와 상태 복구 조작에 focus할 때 하단 내비게이션 위로 완전히
  드러나는 세로 스크롤 경로를 보장한다.
- `prefers-reduced-motion`에서는 페이지·큐 애니메이션과 숫자 패널 pulse를 끄고 실제 박 번호,
  기본 bar의 고정 track과 박 원의 현재 위치 표시는 유지한다. 색만으로 상태를 전달하지 않는다.
- 키보드, 화면 읽기 도구, 터치, 펜, 마우스가 같은 기능에 도달할 수 있어야 한다.
- 로딩은 이전 레이아웃의 크기를 유지하는 skeleton 또는 progress 상태로, 오류는 원인과
  재시도 조작을 함께, 빈 상태는 다음 행동 하나를 명확히 제시한다.

## 2. 폭·높이 구간

폭 구간은 CSS 픽셀 기준이며 각 화면은 아래 구간 사이를 자연스럽게 보간한다.

| 구간 | 가용 폭 | 기본 내비게이션 | 콘텐츠 규칙 |
|---|---:|---|---|
| Micro | `< 360px` 또는 확대 후 동등 폭 | 5개 하단 탭 + 더보기 | 1열, 카드 padding 12px, 짧은 라벨 |
| Compact | `360–599px` | 5개 하단 탭 + 더보기 | 1열, 하단 핵심 조작, sheet |
| Medium | `600–839px` | 세로형은 하단 탭, 가로형은 rail + 더보기 | 1–2열, master/detail은 전환형 |
| Expanded | `840–1199px` | 72px rail | 2열, 보조 패널 접기 가능 |
| Desktop | `1200–1599px` | 216px sidebar | 최대 1200px, 편집기는 2패널 |
| Wide | `≥ 1600px` | 240px sidebar | 최대 1440px, 정보 밀도만 증가 |

별도 높이 구간:

- 메트로놈 설정 sheet와 조작 압축은 폭·높이를 함께 본다. Micro/Compact(`≤599px`)는
  높이 `≤900px`, Medium(`600–839px`)은 `≤820px`, Expanded 이상은 `≤640px`에서
  설정 panel을 sheet로 옮긴다. Medium은 821px부터 stage/조작 2열을 유지하면서 인라인
  설정과 `시작 마디`를 다음 row에 복원해 세로 여유를 빈 공간으로 버리지 않는다. BPM 입력
  시각 힌트는 모든 폭에서 제거한다. 모바일 일반 화면은 원형 박 아래 현재 속도 숫자에서,
  데스크톱 일반 화면은 큰 BPM 숫자에서 직접 입력한다. topbar가 남는 폭 840px 이상에서
  `height ≤539px`일 때 헤더 높이를 52px로 줄인다.
- 모바일 일반 화면의 원형 박 canvas는 별도 row에서 `clamp(64px, 10dvh, 92px)` 높이를 쓴다.
  Medium은 모든 높이에서 stage와 조작을 2열로 놓으며 숫자 panel은
  `clamp(128px, 38dvh, 480px)`, 높이 700px 이하에서는
  `clamp(80px, calc(100dvh - 200px), 240px)`로 조정한다.
  Expanded 이상은 `≤640px`에서 2열로 놓는다. Fullscreen은
  `≤640px`에서 별도 축소하며 `≤320px`에서는 억지로 겹치지 않고
  세로 스크롤로 안전 조작에 도달하게 한다.
- 폭 599px 이하 일반 메트로놈 page는 본문의 가용 높이를 채우고 header·원형 박·속도·박자표·조작·상태
  영역을 제외한 남는 높이를 숫자 panel에 배분한다. page는 `height: 100%`, stage row는
  `minmax(min-content, 1fr)`, 숫자 panel은 `height: 100%`로 채운다. 숫자 wrapper의 최소 높이는
  56px이며 canvas를 absolute로 맞춰 backing store의 intrinsic 높이를 grid 계산에서 분리한다.
  짧은 화면이나 200% 글자 확대에서는 최소 높이를 보존하고 세로 스크롤로 충돌을 피한다. desktop의 기존 박 canvas는
  `dvh`에 따라 원·진행 track을 함께 보간하되 일반 화면 340px, Wide 380px 상한을 유지한다.
  모바일 현재 마디·대기·예비박 문맥은 상단 header에 두며 desktop/fullscreen은 기존 stage 문맥을 유지한다.
- 소프트 키보드가 열린 폼에서는 `dvh` 감소를 따르고 하단 내비게이션을 숨기며 현재 입력과
  저장 버튼이 가려지지 않게 한다.
- 4K·초광폭에서는 콘텐츠를 무한 확대하지 않는다. 본문은 최대 75자 폭, 편집/대시보드
  영역은 최대 1440px, 메트로놈 시각화 핵심 폭은 최대 1100px로 제한한다.

기기 형태와 실행 환경:

- 데스크톱 split view와 모바일 multi-window는 기기 종류가 아니라 실제 CSS 폭으로 판단한다.
- foldable/dual-screen에서 hinge 정보를 제공하는 경우 핵심 재생 버튼·dialog를 hinge 위에 두지
  않고 한 segment 안에 배치한다. 정보가 없으면 Medium/Expanded 단일 열 규칙으로 안전하게
  fallback한다.
- TV·프로젝터·보면대 외부 모니터에서는 `Wide` 규칙과 원거리 모드를 사용한다. hover 없이
  방향키/Enter/Escape로 이동할 수 있고 focus ring을 더 강하게 표시한다.
- 설치형 PWA·Capacitor·브라우저는 같은 콘텐츠 위계를 유지하되, 브라우저 chrome 변화에는
  `dvh`, notch·Dynamic Island·home indicator에는 safe-area를 사용한다.
- 터치스크린 노트북과 펜 태블릿처럼 coarse/fine 입력이 함께 있으면 레이아웃은 폭으로,
  target 크기와 hover는 각각 `any-pointer`/`any-hover`로 결정한다.

## 3. 앱 셸과 내비게이션

- 폭 839px 이하의 모바일 메뉴는 `메트로놈`, `악보`, `앙상블`, `연습`, `더보기`다. 이 폭에서는
  topbar를 제거하고 Bonifacio 복귀, 테마, 설정, 계정·로그인, managed SSO 운영 안내를
  더보기 sheet에서 제공한다. 템포맵, 튜너, 프로젝트, 캘리브레이션도 더보기와 각 맥락 CTA에서 접근한다.
- Micro 하단 탭 라벨은 11px보다 작아지지 않으며 최대 두 줄 안에서 아이콘과 함께 읽혀야 한다.
- Medium은 세로 방향에서 하단 탭, 가로 방향에서 왼쪽 rail을 사용하며 양쪽 모두 `더보기`를 제공한다. Expanded는 아이콘+라벨 rail을 사용한다.
- Desktop 이상은 sidebar를 사용하고 현재 위치를 색뿐 아니라 배경·`aria-current`로 표시한다.
- 브라우저의 `← Bonifacio` 링크는 폭 840px 이상 topbar와 839px 이하 `더보기`에서 같은 탭으로 포트폴리오 홈을 연다. 최소 크기는 44px이며 coarse pointer에서는 48px이다. Capacitor 네이티브 shell에서는 숨긴다.
- AppShell grid는 하단 내비게이션 row를 본문 scrollport와 분리해 같은 공간을 점유하지 않게
  한다. 브라우저 200% 글자 확대 시 두 줄 라벨은 유지하되 높이는 Compact `64–96px`, Micro
  `60–88px`로 제한한다. 본문은 24px 하단 padding과 scroll padding만 두며 이미 예약된
  내비게이션 높이를 다시 더하지 않는다.
- 다크/라이트는 모바일 `더보기`와 폭 840px 이상 topbar의 44px 이상 해·달 버튼에서 바꾼다.
  설정 radiogroup에서도 같은 값을 선택한다. 모바일에는 숨은 topbar 조작이 focus 대상으로 남지 않는다.
- 본문 시작에 skip link를 제공하고 페이지 전환 시 새 `h1`으로 초점을 이동하거나 화면
  읽기 도구에 제목 변경을 알린다.
- 본문 scroller의 좌표는 history entry별로 기억해 뒤로/앞으로 탐색에서 복원하고, 새
  탐색은 맨 위에서 시작한다. browser POP은 모바일 더보기 dialog를 닫아 복원된 화면을
  가리지 않는다.

## 4. 화면별 적응 규칙

### 메트로놈

- 폭 839px 이하 일반 화면은 현재 마디와 시작 대기/예비박 상태를 `.performance-context`로
  상단 header 왼쪽의 단일 DOM에 둔다. 예비박 중에도 `마디 1 · 예비박 4`처럼 마디 번호를
  유지하고 다음 구간이 없으면 `다음: 마지막 구간`은 생략한다. 개인 연습/Section 문맥은
  숨기되 접근 가능한 `h1`은 유지한다.
  desktop/fullscreen은 기존 stage 문맥을 유지한다. 기존 박 슬롯 위에는 가로폭이 넓은
  `.metronome-number` 영역을 둔다. 테두리·둥근 모서리 없이 같은 오디오 frame source의 rAF로
  현재 본박 번호, 예비박 countdown, 예약 대기 `—`만 중앙에 표시한다. 실제 glyph를 측정한
  기존 fit 글자 크기의 80%를 쓰되 panel 크기·배치와 200px 상한 없는 fit 계산을 유지하며 본박 숫자는 `1..beatCount`의 최대 실측 폭을 기준으로
  같은 글꼴 크기와 x 중심을 유지한다. 현재 속도 숫자와 박자표는 원형 박 아래에 나란히 두고
  `BPM` 글자는 숨긴다. 양쪽이 같은 폭인 grid로 속도 숫자의 중심을 고정하고 오른쪽 박자표와 baseline을 맞추며 큰 박 번호
  영역에는 박자표를 표시하지 않는다.
  숫자는 테마 text 단색이며 오디오 progress에 따라 opacity 0.6–1로 pulse한다. 본박/예비박
  경계마다 반복하되 subdivision에는 다시 시작하지 않으며 화면 전체를 점멸하지 않는다.
  정지 중에는 숫자를 고정하고 모션 감소 설정에서는 pulse 없이 실제 박 번호만 갱신한다.
  모바일 일반 메트로놈의 진행 배경은 오디오 `frame.progress`에 따라 메뉴를 제외한 앱 영역을
  진한 주황 `#f47a24`, opacity 0.3으로 왼쪽에서 오른쪽으로 채운다. 진행 전용 `variant="progress"`를 Page 내부에
  fixed로 렌더하고 활성 `.app-shell`에 `isolation: isolate`, 진행 레이어에 `z-index: -1`을
  적용해 앱 표면 바탕 위·모든 콘텐츠 아래에 둔다. `pointer-events: none`·`aria-hidden`을 유지한다.
  상속된 `--mobile-nav-height`만큼 bottom을 제외해 하단 메뉴 위에서 끝낸다. 600–839px
  landscape는 `--rail-width`만큼 left를 제외하고 bottom은 0으로 둔다. 메뉴 배경은 원래 표면을 유지한다.
  큰 숫자 영역의 별도 채움은 없애고 pulse·fit 계산을 유지한다. 정지·예약 대기·reduced
  motion에서는 채움을 비우고 route 이탈·desktop·fullscreen 전환 때 장식 레이어를 제거한다.
  모바일의 기존 radial 배경은 끄고 원형 canvas에도 bar를 중복하지 않는다. 기본 bar·desktop/
  fullscreen·다른 BeatVisualizer는 기존 bar와 reduced-motion 고정 track을 유지한다. BPM 직접 입력은 원형 박 아래 속도 숫자를
  눌러 열며 기존 20–400 dialog·입력 오류·종료 후 해당 숫자로의 focus 복원을 유지한다.
  설정에는 중복 템포 버튼을 두지 않으며 desktop/fullscreen은 기존 표시를 유지한다.
- 진행막대가 없는 원형 박 묶음은 canvas의 가로·세로 중앙에 정렬한다. 박 슬롯은 번호를 상시 표시하고 현재 박을 색·윤곽·크기로 중복 부호화한다. 4/4 기준
  Micro·짧은 landscape는 약 40px급, Wide는 128px 이상의 원 지름을 목표로 한다. 가용 폭에
  모든 박이 읽을 수 있는 크기로 들어오지 않으면 원을 계속 줄이거나 자르지 않고 현재 박을
  포함한 번호 window만 표시하며, 앞뒤의 남은 박은 생략 표시로 알린다.
- 예비박 동안에는 일반 박 원 없이 단독 카운트다운 숫자를 표시하며 기본 bar 사용처는
  진행 track을 유지한다. 기존 beats
  variant의 숫자는 canvas 높이에 맞춰 24–160px로 제한하며 reduced motion에서도 고정 track은
  유지한다. 예약 대기·예비박의 마디·BPM·박자는 최종 anchor를 따르고 첫 오디오 전에는
  박 강조·announcement·반응 배경을 끈다.
- Compact/짧은 화면에서는 재생·탭템포·BPM 단계를 먼저 배치한다. 모든 폭에서 예비박 토글은 메인
  조작에서 빼고 세부 설정 dialog나 인라인 설정 panel에서 같은 저장 동작으로 제공한다.
  stage는 내용 안전 `min-height`를 보존해 상태와 조작을 겹치지 않게 한다. 가용 높이가
  부족한 짧은 화면·200% 확대에서는 세로 스크롤로 재생과 모든 조작에 도달할 수 있어야 한다.
  빠른 `시작 마디` 입력을 숨기는 배치에서는 같은 입력을 sheet 안에 반드시 제공한다.
- Medium 이상에서는 박 슬롯과 재생 상태를 중심에 두고 설정을 하단 패널로 배치한다.
- 정지 상태에서도 `ResizeObserver`와 viewport resize로 canvas backing store와 박 좌표를 즉시
  갱신한다. 재생 시작을 resize 복구 수단으로 사용하지 않는다.
- 박자 select는 네이티브 indicator를 제거하고 select와 같은 상대좌표 wrapper 안에서 하나의
  chevron만 수직 중앙에 둔다. 모바일 BPM 단계는 `−5 / +5`로 줄여 overflow를 방지하고
  접근성 이름에 정확한 증감량을 유지한다. 오른쪽 끝의 `탭` 진입 버튼은 `탭 템포` 접근성 이름을 유지한다.
  범위를 넘는 단계 조작은 20 또는 400으로 clamp하고 정확한 경계에서는 해당 방향 버튼을 비활성화해 무반응으로 보이지 않게 한다. 강세는 내부 숫자 대신
  무음·보통·강박과 다음 상태를 이름으로 알리고, 설정의 예비박은 이름과 색, `켬`/`끔` 글자로
  상태를 중복 부호화한다. 탭 템포의 `다시 탭`과 누적 횟수는 보이는 라벨과 별도 polite status에 동시에 제공한다.
- 모바일 `탭` 버튼은 BPM을 직접 변경하지 않고 조작 영역 전체를 큰 탭 입력판으로 대체한다.
  기본 조작의 ±5·탭은 네모 테두리와 배경을 없앤다. 탭은 0.6875rem의 muted text로
  작게 표시하되 누르는 영역은 48×48px 이상으로 유지하고 키보드 focus 표시는 보존한다.
  재생과 좌우 ±5의 묶음은 조작 영역 중앙에 맞추며 오른쪽 탭의 폭이 중심을 밀지 않게 한다.
  전체 화면 modal을 만들지 않으며 입력판을 두드린 간격만 기존 탭 템포 계산에 사용한다.
  첫 탭은 기준 시각이고 열기·닫기는 횟수에 포함하지 않으며 매 진입 새 측정을 시작한다.
  입력판은 최소 높이 128px을 확보하고 우상단 × 아이콘은 16px, touch target은 48px이다.
  × 또는 Escape로 원래 조작에 복귀하며 탭 버튼에 focus를 복원한다. 폭 840px 이상으로
  바뀌면 입력판을 닫고 데스크톱 직접 탭으로 돌아가며 fullscreen 진입 시에도 측정을
  초기화한다. 데스크톱 직접 탭과 fullscreen 조작은 유지한다.
- 모바일 상단의 보면대 버튼은 제거하고 큰 박 번호를 누르면 인앱 집중 화면을 토글한다. 집중 화면은 메뉴를 숨기므로 진행 배경의 inset을 0으로 두되 콘텐츠 아래 레이어는 유지한다. 집중 화면에는 큰 번호·원형 박·속도/박자표·재생/정지만 남기고 상단·하단 메뉴, ±5·탭·설정을 숨긴다. 다시 큰 번호를 누르거나 입력 dialog가 닫힌 상태에서 Escape로 복귀하며 오디오 재생은 유지한다. 데스크톱의 기존 fullscreen 동작은 유지한다.
  모바일 일반 화면의 세부 설정은 테두리 없는 아이콘만 표시하며 44px, coarse pointer에서는 48px의 터치 영역과 `세부 설정` 접근성 이름을 유지한다.
  모바일에서는 속도 숫자를 눌러 기존 20–400 입력 dialog를 열고, 박자표를 눌러 2/4·3/4·4/4·5/4·6/8·9/8·12/8의 같은 7개 선택지를 가진 dialog를 연다. 박자표 변경 시 기존 앞 박 강세를 보존하고 초과분은 제거하며 추가 박은 보통 강세로 채운다.
- 데스크톱 풀스크린 보면대 모드는 기존 visualizer를 사용한다.
  화면 비율과 관계없이 박 슬롯, BPM, 마디, 예비박 숫자를 보존하며,
  더블 탭/`Escape` 모두로 종료할 수 있다. BPM 입력·템포맵 편집과 보조 문맥은 `inert`와
  `aria-hidden`으로 시각·포커스 양쪽에서 제외하고 설정 panel은 grid flow에서도 제거한다.
  fullscreen 표면 뒤의 topbar·sidebar·bottom navigation도 `inert`/`aria-hidden`으로 묶어
  보이지 않는 AppShell 조작으로 Tab focus가 빠지지 않게 한다.
  템포맵 상태가 나타나면 별도 row에 두어 stage의 가변 높이와 재생 조작을 밀거나 겹치지 않는다.
  일반 화면의 다열 배치와 카드 모서리를 상속하지 않고 `border-radius: 0`의 edge-to-edge 단일
  열로 재설정해 재생 버튼을 화면 중앙에 둔다.
  높이 640px 이하에서는 canvas·BPM·문맥을 연속적으로 줄이고, 320px 이하에서는 내부 스크롤로
  전환해 모든 안전 조작을 겹침 없이 보존한다.
- 폭 839px 이하 일반 화면(집중 화면·fullscreen 제외)은 한 줄 중앙에 `−5 → 재생/정지 → +5`를
  묶고 `탭`을 오른쪽 끝에 작고 은은한 글자로 표시한다. 600–839px의 stage/조작 2열 틀과 세로 여유가 있는
  Medium·긴 phone의 빠른 시작 마디 field는 유지한다. `600–839px`은 모든 높이에서 stage와
  조작을 2열로 나누며, 높이 820px 이하만 설정 sheet를 쓰고 821px부터 인라인 설정과 빠른 시작 마디를
  복원한다. 840px 이상은 820px 이하에서 stage를 줄인 뒤 640px 이하에서 2열로 바꾼다.
  압축·복원 경계 다음 픽셀인 `820/821`, `900/901`, `640/641`과 더 이상 전환점이 아닌
  `1180/1181`의 연속성을 검증한다. 설정 dialog가 열린 상태에서 `820→821` 또는 `900→901`로
  전환해 compact trigger가 숨겨지면, dialog를 닫은 뒤 새로 나타난 인라인 `시작 마디`로 focus를
  복구한다.
  모바일 한 줄의 시각·키보드 DOM 순서는 `−5 → 재생/정지 → +5 → 탭`으로 같게 유지한다.
  `탭` 글자는 좁은 화면에서도 유지하고 접근성 이름은 `탭 템포`다. 일반
  Expanded/Desktop은 재생을 중앙에 두기 위해 시각적으로 BPM 조절 → 재생 → 빠른 설정을
  사용하되 DOM/포커스는 재생 우선을 유지한다. coarse pointer에서는 간격을 먼저 줄여
  재생·두 BPM 단계·탭·시작 마디와 상태 복구 조작의 48×48px 최소 target을 보존한다.
  모바일 stage는 숫자 panel → 원형 박 → 속도·박자표를 세로의 일반 흐름으로 배치한다. 숫자 panel의
  204/116/52px 고정 높이와 recovery의 원형 박·BPM 병렬 배치는 사용하지 않는다. 현재 마디·
  대기·예비박은 상단 header에 유지하며, 짧은 화면·200% 확대에서는 최소 높이와 세로
  스크롤로 상태·표시·조작이 겹치지 않게 한다.

### 템포맵 편집기

- 마디 타임라인만 가로 스크롤한다. 페이지 헤더와 속성 폼에는 가로 스크롤이 없어야 한다.
- Compact는 `타임라인 → 구간 목록 → 선택 속성 → 이동 지시` 단계형 구조와 하단 저장 bar를
  사용한다. Expanded 이상은 타임라인 아래 속성/이동 지시 2패널을 사용한다.
- 표 모드는 CSS grid 모양만 낸 div가 아니라 native `table`·column header·row header로 구성한다.
- 반복·volta·D.C./D.S./Fine/Coda는 JSON이 아니라 이름, 범위, 패스가 표시되는 폼으로
  편집하며 전개 오류 위치와 해결 방법을 즉시 보여준다.
- 행 이동, 분할, 병합, 삭제는 키보드와 터치 모두 제공하며 삭제는 undo 또는 확인을 제공한다.
- 원격 템포맵을 network failure 후 현재 계정의 IndexedDB v3 snapshot으로 연 경우 편집·가져오기·
  저장을 잠그고 “오프라인 읽기 전용”·연결 재확인·내보내기를 노출한다.

### 동기 세션

- 참가 전 화면과 참가 후 무대 화면을 분리한다. 연결 중·재연결·오프라인·늦은 합류·권한 변경을
  서로 다른 상태로 표시한다.
- Compact에서는 박자·현재 마디와 준비·리더 시작/정지를 먼저 노출하고, 참가자 목록은 sheet로 연다.
  핵심 조작은 stage 안의 일반 문서 흐름에 두며 고정 하단 overlay를 쓰지 않는다. 짧은 가로
  화면은 박과 조작을 2열로 나누고, 준비/대기와 준비 인원수는 글자로 보존한다.
- 시작 마디·반복 차수·예비박은 리더의 `재생 설정` dialog, 방 코드·고정 revision·RTT는 접는
  연결 정보에 둔다. 오디오 준비가 필요한 늦은 참가자의 `소리 켜고 합류`를 무대에 표시한다.
- `악보 보기`는 세션 route와 재생을 유지한다. 작은 박 표시와 세션 조작 아래 악보를 배치하고,
  박·조작은 스크롤할 때 상단 sticky로 유지한다. 폭 520px 이상은 압축된 2열 무대를 사용한다.
  세션에 포함된 악보 도구는 일반 문서 흐름에 두어 하단 내비게이션과 겹치지 않게 한다.
- ready/start/stop은 서버 roster/transport acknowledgment 또는 5초 timeout 전까지 pending으로 잠가
  중복 탭을 막는다. Clipboard API 실패 시 선택 가능한 read-only 초대 URL과 재시도를 보인다.

### 악보

- 독립 악보 화면은 현재 마디·BPM·박자·박과 재생/정지를 담은 카드 다음에 악보를 배치한다.
  카드는 재생 중이며 보기 모드일 때만 상단 sticky를 적용하고 정지·매핑·필기 중에는 일반 흐름에 둔다.
  폭 600px 이상은 2열로 압축하며 재생 중 템포맵 연결 상세는 숨긴다. 버튼의 보이는 라벨은
  `재생`/`정지`, `구간 편집`이며 자세한 접근성 이름을 유지한다. Compact 필기·매핑 도구는
  `top: auto`로 기존 상단 위치를 해제해 하단 overlay에 정렬하고, 세션 내 악보에서는 일반 흐름으로 바꾼다.
  로컬 악보의 템포맵 선택과 `구간 편집`도 좁은 폭에서 줄바꿈해 접근할 수 있어야 한다.
- 총보·파트보는 `tablist`/`tab`/`tabpanel`과 roving tab index를 사용하고, 화살표·Home·End로
  선택한다.
- 펜·매핑은 pointer capture한 현재 `pointerId`만 처리해 stylus 입력에 두 번째 손가락이 섞이지
  않게 하고, `pointercancel`에서 임시 입력을 폐기한다. 펜 좌표는 0–1로 저장하되 표시 선은
  `non-scaling-stroke`로 zoom과 무관한 3 CSS px 두께를 유지한다.
- 페이지 전환은 현재 마디 진행으로 자동 수행하되 사용자가 수동으로 이동하면 잠시 자동
  전환을 보류하고 복귀 CTA를 제공한다.
- PDF/이미지의 확대·이동은 악보 영역 안에서만 일어나며 앱 전체 가로 스크롤을 만들지 않는다.

### 튜너·캘리브레이션·로그인

- 튜너 음이름과 센트 값은 짧은 가로형에서도 동시에 보인다. 마이크 권한 거부 상태에는 OS별

## 5. 검증 매트릭스

자동 반응형 smoke는 최소 아래 viewport에서 모든 주요 route를 검사한다.

| 용도 | viewport |
|---|---|
| 200% 확대 효과 폭 | `256 × 568` |
| 최소 Android/확대 경계 | `320 × 568` |
| 소형 iPhone | `375 × 667` |
| 현대 phone | `390 × 844` |
| 큰 phone | `430 × 932` |
| phone landscape | `667 × 375` |
| Compact 높이·폭 경계군 | `320/375/390/430/599 × 701`, `390/599/600/768/820 × 821` |
| Compact 압축 전환 | `599 × 900/901` |
| 작은 tablet portrait | `600 × 960` |
| tablet portrait | `768 × 1024` |
| Medium 경계·연속성 표본 | `839 × 820/840`, `839 × 1180/1181` |
| tablet landscape | `1024 × 768` |
| Expanded 짧은 경계 | `840/844/1024 × 390`, `840 × 420/421`, `840 × 640/641` |
| notebook | `1280 × 720` |
| desktop | `1440 × 900` |
| large desktop | `1920 × 1080` |
| 4K/초광폭 대표 | `2560 × 1440` |

현재 자동 matrix는 52개 viewport의 12개 주요 route 기본 상태에서 페이지 가로 overflow,
viewport 밖 이탈, primary CTA가 viewport 또는 한 번의 정상 세로 스크롤 안에 있는지, 44px
target, 고정 내비게이션 비가림과 새 route `h1` focus를 검사한다. 메트로놈의 기본 상태/조작
비겹침은 이 전체 matrix에서 확인하고, recovery banner는 폭별 압축 구간과
`420/421`, `820/821`, `900/901`, `640/641` 경계 표본에 주입한다. `1180/1181`은 Medium 배치가
두 픽셀 사이에서 연속적인지 별도 비교한다. Fullscreen은 상태 유무 양쪽을
12개 대표 크기에서, coarse pointer의 48px target은 16개 대표 크기에서 검사한다. 32px root
font 확대는 `390 × 600` 대표 context의 핵심 표시 묶음과 조작, `256 × 480`의 BPM dialog
및 `256/320/359/390/419 × 480`, `599 × 700`의 모바일 내비게이션·focus-scroll 경로에서
최초 focus 가시성을 확인하며, dialog focus trap, 키보드 widget 경로, empty/loading/error
변형은 별도 targeted spec에서 검증한다.

다크·라이트 자동 대비 검증은 primary/secondary/muted text의
background/surface/surface-raised 조합, accent의 background/surface 조합과
`--on-accent`/accent를 4.5:1 이상으로 확인한다. `--control-border`는
surface/surface-raised 대비, 고정 progress track은 background 대비를 3:1 이상으로 확인한다.
별도로 고대비/forced-colors, safe-area, 소프트 키보드, 오프라인/재연결을 수동 확인한다.
